## 仮説（1文・falsifiable）
「**ETH/BTC比の相対モメンタム（比が上昇＝ETH相対強→ETHロング/BTCショート、下降＝逆）**に基づく**ドルニュートラルのロングショート・スリーブ（ショート側Fundingコスト実データ込み）**は、（i）未見の確認期間（2023-2026）で**スプレッド方向の予測エッジ（permutation p<0.05）**を持ち、かつ（ii）②（モメンタムL=30・BTC）との**相関がゼロ近傍（|ρ|<0.3）**で、（iii）②単体に上乗せすると**未見期間で合成Sharpe改善 または 最大DD削減**に寄与する」。
→ (i)(ii)(iii) を**全て**満たして初めて採用。**予測単位(i)が立たなければ即打ち切り**（③OBS000027の轍を踏まない）。見かけのスリーブSharpe単独では採用しない（②との分散効果が存在意義）。

## エッジの事前登録（1つに固定・多重検定回避）
- **登録エッジ＝相対モメンタム（相対強弱の順張り）ただ1つ。** ETH/BTC比の**平均回帰**版は本実験では**測定しない**（グリッド探索・両建て検定を禁止）。②が順張りゆえ直交補完と弱気相場での挙動差を狙う、という prescreen 点1の指定に従い相対モメンタムを第一候補として固定する。
- 平均回帰を試したい場合は本実験のリスコープ（結果を見てからの乗り換え）ではなく、選定/確認分離を備えた**別OBSの新規起票**でのみ許可する。

## シグナル定義（固定・可変にしない）
- **比系列**: `ratio[t] = ETH.close[t] / BTC.close[t]`（両者とも `*-daily-binance-2017-2026.csv` の同一UTC日足終値）。
- **ルックバック L = 30 に固定**（②の本番実装 `momentumLookback=30` を流用・準用。prescreen 点2＝新規グリッド探索の最小化）。**Lのグリッド探索は行わない。** 参考診断として L∈{20,60} のスリーブSharpeを**選定期間のみ**で併記してよいが、これは頑健性の可視化であり**採否・確認期間には一切使わない**（可変自由度を作らない）。
- **方向判定**: `momRatio = pctChange(ratio[t-L], ratio[t])`。`NEUTRAL_THRESHOLD = 0.0005`（②系と同一）。
  - `momRatio > +NEUTRAL_THRESHOLD` → **ETHロング / BTCショート**（signal=+1）
  - `momRatio < -NEUTRAL_THRESHOLD` → **ETHショート / BTCロング**（signal=-1）
  - 帯内 → neutral（ポジションなし）
- **リバランス頻度 = HORIZON = 10日**（②系と同一・非オーバーラップ。10日保有→判定更新）。
- **確信度スケール（サイジング）**: 予測単位・スリーブSharpeともにKellyサイジングは使わず**等ノーション固定**で測る（②の`scale=30`は単一資産の順張り用。相対スリーブに新たなサイジング自由度を持ち込まない）。②との合成時の配分ウェイトのみ下記で固定。

## 構成の固定（ニュートラル・Fundingコスト・執行コスト）
- **ドルニュートラル**: ロング側とショート側を**等ドルノーション**（各50%）。βニュートラル版は自由度追加になるため本実験では採らない（ドルニュートラルに一本化）。相関チェック（G3）でβ残差の存在は検出できる。
- **リターン定義（グロス、予測単位用）**: 保有期間の**スプレッドリターン** `spreadRet = signal × ( r_ETH − r_BTC )`、ただし `r_X = pctChange(close[t], close[t+HORIZON])`。Fundingなし（方向エッジの純粋測定）。
- **スリーブ純リターン（Stage2/3用・Fundingと執行コスト込み）**:
  - **Funding**: `loadDailyFundingRate` で `btc-funding-2019-2026.csv` / `eth-funding-2019-2026.csv` を日次集約。あるレッグの日次Funding損益 = `−(ポジション符号) × fundingRateDaily`（loadFundingRateDataの規約「正=ロングがショートに支払う」に従う。ロング=−rate、ショート=+rate）。ペア全体の日次Funding = ETHレッグ＋BTCレッグの合計を**保有日ごとに毎日**加算（ショート側コストを必ず織り込む＝prescreen 点3）。
  - **執行コスト**: リバランスで方向転換またはリバランスが発生した日に、両レッグ×往復分を `DEFAULT_EXECUTION_COST`（takerFee＋slippage）で控除。`funding-carry-delta-neutral.ts` の `FLIP_COST = 4×ONE_WAY_COST` と同水準の考え方を踏襲（2レッグ×往復）。ポジション継続（同方向）の日は執行コストなし。
  - **Fundingデータ制約（正直に明記）**: Funding履歴は **2019-09-19以降**しか存在しない。したがって**Fundingコスト込みのスリーブSharpe・②との合成（Stage2/3）は選定=2019-09〜2022、確認=2023-2026**で測る。**予測単位（Stage1・Fundingなしのグロス方向）のみ** ETH/BTC日足の全期間（2017-08〜）を選定に使える。この非対称は結果に明記すること。

## 段階的評価（Stage1→2→3。前段通過が後段の前提）

### Stage 1 — 予測単位（スプレッド方向の予測可能性）＝最初の関門・kill判定
相対モメンタム signal が、②④⑤⑥を通さず**単独で**HORIZON=10日先の**スプレッド方向**（`sign(r_ETH − r_BTC)`）を当てるか。非オーバーラップ（step=HORIZON）、permutation検定。
- **選定期間で in-sample 特性を確認**（下記）→ **確認期間（2023-2026・未見）で本判定**。
- **G1（採用の必須前提・未達なら即打ち切り）**: 確認期間で `hitRate > 50%` **かつ** `permutation p < 0.05`（`N_PERM = 5000`, `seed = 20260704`, `momentum-robustness.ts` と同一の並べ替え法）。
  - **G1未達 → 本実験は打ち切り（Stage2/3に進まない）。** 相対モメンタムに未見期間の生エッジなし＝③と同じく土俵に価値なしと結論。

### Stage 2 — ニュートラル・スリーブ単体（Fundingコスト込みSharpe）
G1通過を前提に、Fundingと執行コスト込みのスリーブ純リターン列で年率Sharpe・累積リターン・最大DDを算出。
- **G2（存在の必要条件）**: 確認期間で**スリーブ純Sharpe > 0**（Fundingコスト控除後もプラス）。DDは開示のみ（数値ゲートは合成側G4で持つ）。
- G2はスリーブが「壊れていない」ことの確認であり、**G2単独では採用しない**（見かけSharpeで採らない＝prescreen 点6）。

### Stage 3 — ②との合成（採用の主ゲート＝分散効果）
スリーブ純リターン列と、②単体（BTC・`momentumLookback=30, momentumConfidenceScale=30`のパイプライン）のリターン列を突き合わせ、相関と合成後の改善を測る。
- **②単体の定義**: `simulatePortfolio` を BTC `btc-daily-binance-2017-2026.csv` で本番構成（`horizon:10, k:30, initialEquity:1_000_000, momentumLookback:30, momentumConfidenceScale:30`）で確認期間に回し、`equityCurve` から日次（またはトレード単位）リターン列を得る。参考としてETHでも同時算出し併記。
- **合成ウェイト（回す前に固定・HARKing防止）**: 選定期間（2019-09〜2022）の各リターン列の標準偏差から**逆ボラティリティ（リスクパリティ）ウェイトを算出し凍結**。確認期間ではこの凍結ウェイトのみを適用（確認データでウェイトを最適化しない）。副次として**素朴50/50**も併記。
- **G3（低相関＝存在意義）**: 確認期間で `|corr(スリーブ純リターン, ②リターン)| < 0.3`。
- **G4（合成の上乗せ・下記いずれかを満たす）**:
  - (a) **合成Sharpe改善**: 凍結ウェイト合成の確認期間Sharpe − ②単体Sharpe **≥ +0.15**、かつ最大DDが②単体比 **+2pt を超えて悪化しない**。**または**
  - (b) **合成DD削減**: 凍結ウェイト合成の確認期間 最大DD − ②単体 最大DD **≤ −5pt**（5ポイント以上削減）、かつSharpeが②単体比 **−0.05 を下回って悪化しない**。

### 採用 / 不採用（回す前に確定）
- **採用**: **G1 かつ G2 かつ G3 かつ G4** を確認期間（2023-2026）で全て満たす。
- **不採用**: 上記いずれか未達。特に:
  - **G1未達** → 即打ち切り（予測単位で無エッジ）。
  - **G3未達（|ρ|≥0.3）** → ②と相関が高く「第3の収益源」の前提が崩れる＝分散価値なしで不採用（たとえ単体Sharpeが高くても採らない）。
  - **G4未達** → 合成しても改善もDD削減もしない＝上乗せ価値なしで不採用。
- 参考: ②単体BTCの現状Sharpe≈0.40〜0.67（設定・期間による）。合成Sharpeがこの範囲を分散効果で押し上げるか、DDを実質的に削るかが本質。

### kill基準（チューニング逃避・HARKingの禁止）
事前登録した本spec（エッジ=相対モメンタム1本、L=30固定、ドルニュートラル、HORIZON=10、Funding規約、凍結ウェイト、G1〜G4）の下で未達なら、**仮説を棄却して不採用で停止**する。確認結果を見てから **L・neutral閾値・リバランス頻度・エッジ方向（順張り↔平均回帰）・ニュートラル方式（ドル↔β）・合成ウェイト・レジーム窓・permutation seed を調整して再測定してはならない。** 別案は本実験のリスコープではなく別OBSの新規起票でのみ許可する。

## 選定 / 確認プロトコル（過学習の炙り出し・N=2の固有リスク対応）
prescreen の最重要指摘: **N=2ゆえ「別資産でのOOS」（OBS000019/028を捕えた武器）が使えない**。代替として**時系列の厳格分離＋permutation**に一層依存する。
- **選定（探索・in-sample特性把握）**:
  - 予測単位（Fundingなし）: ETH/BTC日足 **2017-08〜2022-12-31**。
  - スリーブ／合成（Funding込み）: **2019-09〜2022-12-31**（Funding履歴の開始に律速）。
  - 用途: L=30は②から継承済みで**本データで選定しない**ため、選定期間は主に「エッジのin-sample有無・レジーム別挙動・逆ボラウェイト凍結」に使う。確認期間の閾値・設定調整には一切使わない。
- **確認（未見・本判定）**: **2023-01-01〜データ末尾（≈2026上期）**。選定に一切使わない。G1〜G4はここで判定。
- **確認期間の内部頑健性（縮退リスク対応・下記「縮退リスク注記」と対）**: 確認期間を**前半/後半の2分割**し、両半でG1のhitRate・スリーブSharpe・②との相関を**それぞれ生出力**（片方の1本トレンド依存でないかをCが叩けるように）。加えて**スリーブ純PnLへの寄与が最大の単一リバランス（top-1保有）の寄与率**を出力（1〜2発依存の検出）。

## 測定範囲
- **期間**: 選定=予測単位2017-2022／スリーブ2019.9-2022。確認=2023-2026（末尾は2026上期を含む点を結果に明記）。
- **資産**: **BTC＋ETHの相対（ペア必須）**。②単体比較はBTC主・ETH併記。
- **レジーム別分解: 要（正直な開示を必須）**。以下の固定窓でスリーブ純リターンの Sharpe/累積Ret/最大DD と（可能なら）②との符号関係を個別出力する:
  - **R1 アルトシーズン/ETH相対強**: 2020-07-01〜2021-05-31（DeFi Summer〜2021アルトラリー）。※選定期間・in-sample。
  - **R2 BTCドミナンス/リスクオフ・2022弱気窓**: 2022-01-01〜2022-12-31。※選定期間・in-sample。**②が最も苦手な弱気相場でニュートラル・スリーブがβを抜いて別挙動を示すかの核心窓**。
  - **R3 確認・回復/直近**: 2023年 / 2024年 / 2025-01-01〜末尾（各年individually）。※未見・OOS。
- **重要な限界（回す前に明記・Cへの申し送り）**: prescreen指定の分離（選定〜2022／確認2023-）に従うと、**②の弱点である2022型のフル弱気相場(R2)は選定期間＝in-sample**に入る。よって「弱気相場補完」の証拠はR2では**in-sample（弱い証拠）**であり、**採用可否のOOSゲート（G1〜G4）は2023-2026(R3)の合成改善/DD削減に置く**。R2は挙動開示（characterization）に留め、これを採用根拠に格上げしない。
- **予測単位 と パイプライン（スリーブ＋②合成）の両方を測定する**（片方だけは禁止）。同一spec内で並記出力。

## 縮退リスク注記（C品質チームが最初に叩くべき論点）
- **N=2の相対＝「ETH/BTCという単一スプレッドへの1本張り」に縮退**する。クロスセクションの分散効果はほぼ得られず集中リスクが高い。選定期間（2019-2022）のETH/BTC比は大きなトレンド（上昇→反転）を描くため、**順張りエッジは選定期間で容易にフィットして見える**。
- したがってCは以下を最初に検証すること（本specは対応する生データを必ず出力させる）:
  1. **確認期間の前半/後半どちらでもG1が立つか**（片側1本トレンドの継続に過ぎないのでは、という疑い）。
  2. **スリーブSharpeが単一の大リバランス（top-1寄与率）に依存していないか**。
  3. **G3の低相関が確認期間全体の平均で薄まっているだけでないか**（前半/後半別の相関を確認）。
  4. **Fundingコスト控除後もエッジが残るか**（コスト無視の見かけエッジの排除。G2で担保）。
- 上記いずれかで脆弱性が露呈すれば、G1〜G4を数値で満たしても**Cは偽陽性として不採用を宣告してよい**（見かけの数値クリアより頑健性を優先）。
