## 2. spec §2 合否の厳密な当てはめ（判定はC）

### G0-1（履歴深度・主軸N=30ティア）＝ **未達**

C再検算（生JSONから機械集計、`covers3YearsFrom`/最古日/Funding最古で独立計算）:

| 指標 | 実測 | spec N=30達成閾 | 判定 |
|---|---|---|---|
| 日足 3年ライン(≤2022-07-05) | **14本** | 30本以上 | ✗ |
| 日足 2022通年カバー | **14本** | 20本以上 | ✗ |
| Funding 3年ライン | **0本**（最大90日） | （両系列必須） | ✗ |
| **両系列(日足AND Funding) 3年** | **0本** | 30本以上 | ✗ |

- spec達成の定義は「**日足OHLCV＋Funding両系列**が3年ラインから連続取得できる銘柄が30本以上」。Fundingが全銘柄90日で枯れるため**両系列3年＝0本**。**厳密なspec達成の定義では0本＝完全未達。**
- 日足単独で緩めても**14本 < 20本**＝spec未達クロース（「3年連続取得が20本未満」）に該当。**どちらの読み方でもG0-1＝未達。**
- **spec意図（N=20〜50拡張）との整合評価（C判断）**: 拡張の前提は「幅を増やせば賭けの本数が増える」だった。実データは**深さ×幅のトレードオフ**を露呈する。直近数年なら50本組める（2026-07で50本）が、**3年遡ると14本、2022弱気レジームをカバーするのも14本**まで縮む。N=50は「履歴の薄い新規上場トークン化商品（MSTR/XAU/SOXL/SPCX等の株・金連動系）」で埋まっており、これらは3年前に存在しない。**「N=20〜50のブレッドで3年横断バックテスト」という当初の土俵は、Bitget公開APIの深さ制約により3年ラインでは14本に縮退する。** これは蜃気楼ではなく物理制約であり、N再定義でも救えない（14本の壁はデータ可用性そのもの）。

### G0-2（サバイバーシップ排除）＝ **達成せず（公開API不可を確定・外部再構成は未実証）**

- **公開APIで死銘柄履歴は取得不可**を確定（SRMUSDT: 実在した廃止銘柄→code 40309 "removed"、candles本体0件）。code識別（40309廃止／40034不存在）は成功したが、これは「かつて存在した」の判定に使えるだけで、**履歴データ本体は配信されない**。spec達成条件（公開APIから廃止3件のhistory取得）は**明確に不成立**。
- spec部分達成条件（外部無料ソース＋アナウンスで廃止銘柄の上場/廃止日・当時流動性を**3件実証**）は、**B が §2手順4を実施しておらず未実証**。よって部分達成にも到達していない。
- → **現時点でサバイバーシップ排除は無料手段では立っていない。** prescreenのストップ条件「サバイバーシップを含めない横断バックテストは、どれだけ良くても採用しない」に直撃する。

### G0-3（PITユニバースの機械的再現性）＝ **部分達成**

- (1)再現性・(2)先読み排除: **現行銘柄で機構は動作**（月次13リバランスで25〜50銘柄が決定的に構成、as-of深度が単調増加＝先読みなしの構造）。PASS。
- (3)死銘柄ライフサイクル組込み: G0-2で死銘柄データが無いため合成データでの実証が必要だが、**v2出力は現行生存銘柄のみで、死銘柄の出入りを組み込んだ実証物が見当たらない**。
- → spec部分達成の定義「(1)(2)は現行銘柄で満たすが、(3)の死銘柄組込みがG0-2のデータ制約で実データ実証できない」に**厳密一致＝部分達成**。

| spec分岐 | トリガー条件 | 今回の充足 |

**差し戻し（G0-1未達）と保留(a)（G0-2）の両トリガーが同時発火する。** どちらを主にするかがCの判断点:

- **差し戻しの本旨**は「N・履歴起点・対象取引所の再検討をS/Aに戻す」。しかし14本の壁の原因は**N選択ミスではなくBitget公開APIの深さ物理制約**。N再定義・履歴起点緩和・リバランス設計変更のいずれでも、**死銘柄データもFunding深度も生まれない**。よってA/Sに差し戻しても空振りになる（前回の「実装バグ差し戻し」とは性質が違う＝今回は正しく実装した上での真の制約）。
- **本質的ブロッカーは2つとも「無料手段では解けない」**: (i)死銘柄履歴（サバイバーシップ）、(ii)Funding 3年深度。これらは「**有料データ調達の是非**」という技術検証の範囲外の投資判断であり、**まさに保留(a)の定義＝S経由で司令塔判断に上げる**に該当する。

→ **最も妥当な扱い＝分岐(a) 保留・司令塔上申。** 差し戻しトリガーも成立している事実は上申文に併記する（負の資産の完全記録）。

## 4. スリーブ別の切り分け（前回予告の確定 / task point 4への回答）

前回判定書末尾の予告（「日足モメンタムなら成立／Fundingキャリーと完全サバイバーシップ排除は制約残」）は、**再測定で確定した**。

### Stage 2（横断Fundingキャリー）＝ **不成立の確定（負の資産化）**
- Funding履歴は公開APIで**平均72日・最大90日**で真に枯渇（バグでなく `history-fund-rate` エンドポイント固有の制約。C独立再現済み）。両系列3年＝0本。
- **3年横断Fundingキャリーの土俵は無料Bitget APIでは原理的に立たない。** N変更・仕様変更で救えない。有料Funding履歴プロバイダが必須。→ **Stage 2は無料手段では差し戻し相当の不成立**として記録。

### Stage 1（横断モメンタム）＝ **保留(a)に包含（GOもBも出さない）**
- 日足は7年深く（BTC 2019-07・2524日）、Stage 1の価格データ土俵自体は無料APIで**深さは足りる**。
- しかし **(i) 3年ライン到達14本 < N=20下限＝ブレッド未達**、**(ii) サバイバーシップ（G0-2）が無料手段で未解決**。この2点でGOの要件を満たさない。
- **14銘柄の現行生存のみでモメンタムを回すことは技術的には可能だが、それは「生存銘柄のみ＝上振れバイアス」を抱えた検証**であり、prescreenストップ条件に真正面から抵触する。

### モメンタム限定GOを出さない理由（偽陽性の最終防波堤としての判断）
task例示の「モメンタム限定GO上申」は**意図的に採らない**。理由:
1. 14本 < spec下限20本（ブレッド未達を事後に緩めるのはHARKing）。
2. サバイバーシップ未解決の14生存銘柄バックテストは、過去に本PJが繰り返した**「予測単位では有望でもポートフォリオで全滅」「生存バイアスで上振れ」の罠**の入口。ここでGOを出すことは、Cの存在理由（偽陽性製造機を止める）に反する。
3. 「探索的・非採用前提」でN=14現行銘柄を回す選択肢は**分岐(b)の性質に近い**が、spec(b)はG0-1=達成を要件とするため厳密には(b)にも当てはまらない。よってこれは**Cが独断でGOにせず、保留(a)の中で司令塔が選べるサブオプション**として提示するに留める。

## 6. 上申文（S経由・司令塔判断事項）

**Stage 0の結論: 無料Bitget公開APIだけでは、当初設計（N=20〜50・3年深度・サバイバーシップ排除の横断バックテスト）は成立しない。** 内訳:

1. **日足モメンタムの価格土俵は深さ十分（7年）だが、3年ラインで幅が14本に縮退**（N=20下限未満）。
2. **横断Fundingキャリー（Stage 2）は無料APIでは不成立確定**（Funding 90日枯渇）。有料Funding履歴が前提。
3. **サバイバーシップ排除は無料手段で未解決**（死銘柄履歴が公開API非配信、外部再構成は未実証）。

**司令塔判断を要する分岐（技術検証の範囲外）:**
- (A) **有料データ調達に投資するか**（死銘柄履歴＋シンボル上場/廃止台帳＋Funding長期履歴のプロバイダ）。投資すればN拡張・サバイバーシップ排除・Fundingキャリーが同時に開ける可能性。
- (B) **無料の範囲で"探索的・非採用前提"に土俵を縮小するか**（現行生存14〜50銘柄・日足モメンタムのみ・サバイバーシップ上振れ明記の予備検証）。ただし採用判定には載せられない（prescreenストップ条件）。
- (C) **本テーマを一旦保留し、他の土俵転換軸（短時間足高頻度化・非対称サイジング）を先行させるか**。

Cの推薦: **無料手段での「採用前提の」横断検証はここで一旦停止（保留）が妥当。** モメンタム限定でも生存バイアスを抱えたまま採用ラインに乗せることは、本PJの偽陽性回避方針に反する。有料データ投資の是非（選択肢A）を司令塔判断に上げるのが本筋。
