## 2. 観察の頑健性チェック（記述的）

### 2-1. 予測単位×パイプライン整合（OBS000025型の乖離がないか）
- **整合（同方向・負）。** Config A: メイン横断IC=-0.0720、ネットSharpe=-0.1013、累積-32.50%、最大DD-50.95%。Config B: IC=-0.0367、ネットSharpe=-0.0410、累積-49.60%。予測単位が負でパイプラインも負＝乖離なし。過去の「予測単位◎→パイプライン×」の罠には該当しない（そもそも予測単位が◎でない）。

### 2-2. 時系列再現（選定/確認の一貫性）
- **両半とも負で一貫（C独立集計）**: 選定期間(2022-01〜2024-06) 平均IC=-0.0893(n=30)、確認期間(2024-07〜2026-07) 平均IC=-0.0513(n=25)。片方が正で片方が負という「暴れ」（OBS000029型のN=2縮退の兆候）はなく、**負のエッジが時間的に安定**＝「芽なし」がノイズの偶然でない傍証。

### 2-3. レジーム分解（C独立集計）
| レジーム | 期間 | 平均IC | ネットSharpe | ネット累積 |
|---|---|---|---|---|
| R1 弱気/2022 | 2022-01〜12 | -0.2560 (n=12) | -1.3738 | -22.6% |
| R2 回復 | 2023-01〜2024-12 | +0.0095 (n=24) | +0.0498 | -16.0% |
| R3 直近 | 2025-01〜2026-07 | -0.0589 (n=19) | +0.5710 | +12.0% |
- 横断モメンタムの既知の弱点（反転/総崩れ局面のDD）どおり、**R1で壊滅**（IC-0.256・Sharpe-1.37）。R2はIC実質ゼロ、R3はIC負だがSharpeプラスとICとポートフォリオの符号が食い違う（n=19の小標本ノイズ・ネット累積+12%は生存バイアス上振れを割り引く必要）。R2/R3のネットSharpe>0を「弱い示唆」と読むのは危険＝ルーブリック②の他条件（全期間平均IC>0 かつ perm p<0.05）を全く満たさないため不成立（下記2-5）。**レジーム越しに芽が立つ像は描けない。**

### 2-4. 統計的頑健性（permutation・n）
- **メイン横断IC permutation は正しく実装され、結果は明確に非有意**: Config A perm p=0.9766、Config B p=0.8742。これは「観測平均IC以上が帰無で出る割合」で、平均ICが負のため大部分の並べ替え（≒0）が観測値を上回る＝**観測エッジが乱数より悪い側**であることを正しく示す。IC t値も A=-1.5110／B=-0.8494 で正の有意性なし。**n**: 月次55期間／ポートフォリオ54ヶ月＝時系列長は十分。held-out各群N=7は低パワー（B自身が注記）。
- ⚠ **ポートフォリオ permutation p（Config A=0.8382／B=0.0660）は無効な検定**（§3-2で詳述）。特にConfig Bの0.0660を「有意に近い」と読んではならない。

### 2-5. ルーブリック§5への当てはめ（Cが記述・採否ではない）
- spec §5 記述①「芽なし」のトリガーに**複数該当**: (i) Config A全期間平均IC ≤ 0（-0.0720）、(ii) permutation p ≥ 0.10（0.9766）、(iii) ネットSharpe ≤ 0（-0.1013）。**いずれか1つで「芽なし」だが3つとも該当**。記述②「弱い示唆」は必須条件（平均IC>0 かつ perm p<0.05 かつ held-out同符号 かつ ネットSharpe>0が3レジーム中2つ）を先頭2条件で既に満たさない。
- **記述: 「芽なし」。** かつS決定メモの非対称性（生存バイアス上振れ前提でも芽なし＝情報価値が高い側）に該当。

## 3. 監査で検出した実装欠陥（記録の正確性のため訂正必須）

> いずれも「良い数字を捏造する」方向ではなく、B報告の一部を無効化する欠陥。負の結論は不変だが、**held-out IC=1.0000 の「符号一致」というB報告は撤回されるべき**。

### 欠陥① held-out 銘柄IC=1.0000 は退化バグ（情報価値ゼロ）＝B報告の再解釈は誤り
- **現象**: `heldOutAnalysis.selectionIC=1.0000` かつ `confirmationIC=1.0000`（両群とも厳密に1.0）。メイン横断ICが-0.072なのに群別ICが両方+1.0という時点で内部矛盾。
- **原因（スクリプト L720-733・L768-782）**: held-out関数内の `fwdData` は `momData.map(...).filter(...)` のみで**フォワードリターンでソートしていない／ランクを振り直していない**（メインIC L462-473 が持つ `.sort((a,b)=>b.ret-a.ret).map((x,i)=>({...x,rank:i+1}))` が欠落）。結果、`fwdData` はモメンタム順のまま。続く
  `momRanks = momData.map(m => momData.findIndex(mm=>mm.symbol===m.symbol)+1)` = [1,2,…,N]、
  `fwdRanks = fwdData.map(f => momData.findIndex(m=>m.symbol===f.symbol)+1)` も **fwdDataがmomData順のため [1,2,…,N]**。
  **両配列が常に恒等一致→ spearman=1.0 がデータに依らず確定的に出る。** C独立再現（実データの1リバランスで両配列とも `1,2,…,13` を確認済み）。
- **含意**: held-out IC=1.0000 は**シグナルの符号一致でも過学習でもなく、フォワードリターンを一度もランク化していない計算バグの産物**。**「符号一致するがメインICが負なので情報価値逆向き」というB報告の解釈は成立しない**（比較すべき実ICが計算されていない）。→ selection/confirmation（held-out銘柄）分割は**実質的に未実施**。
- **差し戻し（Bへ）**: held-out関数の `fwdData` を（メインIC同様に）フォワードリターン降順でソートしランク付けした上でspearman ICを再計算すること。ただし本探索の負の結論には影響しない（下記§4）ため、**探索の再走は司令塔判断（有料データ再起票を検討する場合）まで保留可**。少なくとも記録上「held-out ICは計算不能（バグ）」と訂正する。

### 欠陥② ポートフォリオ permutation p は検定として無効（power ゼロ）
- **現象**: `portfolioResults.permutationPNet` A=0.8382／B=0.0660。
- **原因（スクリプト L648-657）**: 既に確定した月次ネットリターン系列 `portfolioMonthlyReturnsNet` を**シャッフルしてSharpeを再計算**している。Sharpe=mean/std×√12 は系列の並べ替えに対して**不変**（mean・stdは順序に依らない）。C実測: 200回シャッフルでSharpeの変化は最大 3.19e-16（浮動小数点誤差のみ）。
- **含意**: `permSharpe >= netSharpe` の成否は浮動小数点丸めの向きで決まるだけで、**この検定は何も検定していない**。報告値0.8382/0.0660は乱数ノイズ。**特にConfig Bの0.0660を「有意に近い」と誤読してはならない。** specの意図（§4-2「月次ポジション符号を保持しフォワードリターンをシャッフルして帰無分布を生成」）は**ポジションとリターンの対応を崩して再計算**することだったが、実装は完成後リターン系列を並べ替えたのみで意図を実現していない。
- **差し戻し（Bへ）**: ポートフォリオpermutationは「各リバランスでフォワードリターンを銘柄間シャッフルしてからLSポートフォリオを再構築」する方式に修正。ただしメインIC permutation（L497-513・銘柄間でfwdランクをシャッフル）は**正しく実装されており**、予測単位の非有意性（p=0.98/0.87）は信頼できるため、探索の結論は揺るがない。

### 補足: メイン横断ICの計算は正しい（検証済み）
- メインIC（L462-480）は一見トリッキー（`fwdRanks` にモメンタムランクを流用）だが、C独立の3銘柄テストで正しいSpearman IC（完全逆相関で-1.0）を返すことを確認。`fwdData` を明示的にリターン降順ソート＆ランク付けしている点が欠陥①との決定的な差。よってメインIC・時系列分割・レジームIC（いずれも同じ正しいメインIC経路を使用）は信頼できる。
- 先読み排除も適正: モメンタムは `[idx-L, idx]`（過去）、フォワードは `[idx, nextMonthEnd]`（未来）、`getClosestCandleIndexOnOrBefore` によるas-of参照でルックアヘッドなし。Config B は as-of PIT フィルタで先読み排除。

## 4. 欠陥が探索結論に与える影響（なぜ「芽なし」が揺るがないか）

2件の欠陥はいずれも**「芽なし」の負の結論を守る側**にある:
- 欠陥①（held-out）が仮に正しく計算されても、held-out各群N=7の低パワーであり、かつメイン全体ICが-0.072で非有意である以上、群別で正のエッジが立つ蓋然性は低い。少なくとも現状「held-outで再現した」という主張は**根拠を失う**（バグ由来のため）。
- 欠陥②（ポートフォリオperm）を修正しても、ネットSharpeが両config負・メインIC permが明確非有意という事実は変わらない。むしろ無効な0.0660という「紛らわしい低p」が除去され、結論はより明確に「芽なし」へ寄る。

**したがって探索的所見「芽は見えなかった」は堅牢。** ただし記録には「held-out・ポートフォリオpermの2検定はバグで無効＝実質未実施」と明記し、B報告のheld-out符号一致の記述は撤回する。

## 5. 司令塔への示唆（境界条件④に従う・採用ではない）

- 本探索は**採用プロセスに接続しない**（境界条件①④）。以下は**有料データ投資（選択肢A）の是非を検討する際の参考情報**に限る。
- **参考所見**: 生存バイアスが上振れに効く現行14〜50生存銘柄・日足・L=30横断モメンタムでも、コスト後・複数レジーム・時系列両半で一貫して負。**「芽なし」は非対称予備調査で情報価値が高い側**であり、有料データ投資（死銘柄履歴＋上場/廃止台帳＋Funding長期履歴でサバイバーシップ排除した横断BT）の**事前確率を引き上げる材料は得られなかった**。
  - 留保: これは「横断モメンタムというクラス全体の死刑宣告」ではない。(i) L=30単一・月次テルシル・14〜50銘柄という限定条件下の観察であり、(ii) 生存バイアスは上振れ方向なので「本当の（死銘柄込みの）横断分散」はさらに厳しい可能性が高い一方、ユニバース構成/リバランス/ホライズンが変われば像が変わる余地は残る。ただしその探索は**有料データ整備後の別OBS**でのみ行う（HARKing・スコープ内乗り換え禁止）。
- **有料データ投資を起票する場合の必須前提**（再掲・境界条件④）: 死銘柄履歴＋上場/廃止台帳＋Funding長期履歴を整え、サバイバーシップ排除済みの横断BTを別OBSで正式起票。今回結果は「事前確率の参考」以上の重みを持たせない。そして上記2件の実装欠陥（held-out・ポートフォリオperm）を**修正してから**走らせること。
