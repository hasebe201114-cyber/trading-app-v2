## 2. シグナルの事前登録（1セットに固定・グリッド探索禁止・HARKing防止）

026の「Wに敏感＝過学習温床」を、**選定データへのフィットではなくパラメータの理論固定＋グリッド禁止**で封じる（OBS031と同型の設計判断）。以下を本specの値で**ハードコード**する。

- **構成（固定）**: 現物ロング×perpショート、**等ノーション**（各レッグ名目＝正規化1.0）。ファンディング正のときショートperpが受取＝平時の収益源。
- **平滑化窓 W = 7 日（固定・理論根拠＝グリッド探索禁止）**: 日次合算funding（1日3イベント＝8h×3の合算）の**過去W=7日移動平均の符号**でレッグ方向を決める。026がW≥7で反転往復コストを吸収した実測（prescreen §OBS026整理）を理論根拠に**W=7単一値で固定**。W=1/3/14…等のグリッド探索・選定期間での最適W選定は**禁止**（自由度を作らない）。
  - `sign(SMA_7(funding_daily)) > 0` → 現物ロング×perpショート（順キャリー・ショートが受取）。
  - `sign(SMA_7(funding_daily)) < 0` → **現物ショート×perpロング（反転）**（逆キャリー・ロングperpが受取＝弱気でfunding負転時に払う側に回らない）。
  - 反転が発生した日（符号が前日から変わった日）に**4レッグ往復コスト（BTC24.064/ETH24.224bps）を控除**。
- **先読み排除**: W=7 SMAは **t−1 までの過去fundingのみ**で算出（tのfundingは含めない）。ベーシスP&L・funding受払は当日確定値。
- **サイジング原則（固定）**: 予測単位（Stage 1-A）は**等ノーション**。スリーブ（Stage 1-B）は後述**CVaR基準サイジング**（Sharpe基準Kelly禁止＝prescreen §Kelly警告・C必須条件A）。**Sharpe/ボラ基準のKelly・フラクショナルKellyは持ち込まない。**
- W・レッグ構成・SMA窓・反転ルールの**探索・最適化は一切行わない**。別ルール（ベーシスストップ・レジーム減量・W可変）を試したい場合は本実験のリスコープでなく**別OBSの新規起票**でのみ許可。

## 3. レバレッジ帯の事前登録（複数シナリオの並記・成績で選ばない）

**C条件Aに従い、レバレッジは「グリッド最適化」でなく「複数シナリオの並記」として扱う。** 成績（利回り・Sharpe）を見てレバを選ぶことを**禁止**する。

- **検証レバレッジ帯（固定・並記）**: ショートperpレッグの **L ∈ {3倍, 5倍, 10倍}** の3シナリオを**並列に全て報告**する。
- **採否判定は最低レバ帯（3倍）のみで行う**（§7 kill-2）。5倍/10倍は「資本効率を上げるとテール被害・清算がどう悪化するか」を可視化する**情報開示目的の並記**であり、**利回りが高いという理由で5倍/10倍を採用に選んではならない**（HARKing禁止）。
- 各レバ帯の初期証拠金率 IMR＝1/L（3倍→33.3%・5倍→20%・10倍→10%）。**現物ロングレッグは全額自己資本保有（レバレッジ無し・借入コスト0）**、ショートperpレッグのみ証拠金を差し入れる（Stage0前提を踏襲）。

## 4. 清算シミュレーションの具体設計（C条件A・最重要・本Stage 1の核心）

Stage 0の「窓初日固定エントリ＝暴落=下落でほぼ必ずfalse」という同語反復モデルを**廃止**し、以下の**連続保有・日次MTM・証拠金勘定・追証・funding反転による証拠金枯渇**を実装する。**清算=falseを前提にサイジングしない。**

### 4-1. mark価格系列（清算トリガーの基準・C条件D）
- 実取引所の清算は**mark価格**基準。Stage 0はmark klines深度不足でlast採用（`20-verdict-stage0.md`条件D）。Stage 1では **Binance perp mark price klines（`markPriceKlines`）を各テール窓＋連続期間で再取得を試みる**。
  - mark klinesがテール窓を連続カバーできる場合＝**清算トリガー・ベーシスはmark基準**で構築。
  - mark klinesがテール窓に届かない場合＝**last価格で代用し「mark非可用のためlast代用」と明記**。last価格は薄商い時に瞬間乖離を過大計上＝清算を**過大**にカウントする向き（保守側＝偽陰性でなく偽陽性側）であることを注記（安全側の代用）。

### 4-2. ショートperpレッグの証拠金勘定（連続・日次更新）
各レバ帯 L について、ショートperpレッグの証拠金勘定 `margin_t`（名目に対する率）を**連続日次で更新**する:
- **初期証拠金**: `margin_0 = IMR = 1/L`（3倍→0.333 等）。
- **日次更新**:
  `margin_t = margin_{t-1} + perp_short_mtm_t + funding_flow_t`
  - `perp_short_mtm_t = −(perp_t/perp_{t-1} − 1)`（ショートなので価格上昇＝損。mark価格ベース）。
  - `funding_flow_t = ±funding_daily_t`（順キャリー方向でショートが受取＝＋、funding負転で払う＝−。**funding反転による証拠金消耗をここでモデル化**＝C条件Aの必須要素）。
- **維持証拠金率 MMR = 0.5%（＝0.005・業界標準の仮置き・Bitget API非配信）**。**⚠ 記録衛生（C条件D）**: MMRは Bitget contracts API が該当フィールドをundefined返却（`run-g0-3.log`）ゆえ**「業界標準の仮置き（API非配信）」と明示**する。「Bitget API取得」と表記しない。
- **清算判定**: `margin_t < MMR × (現在名目)` となった時点（＝ショートの含み損＋funding払いで証拠金維持率が維持証拠金率を割った時点）を**清算イベント**とする。
  - 参考清算価格式（ショート）: `P_liq = P_entry × (1 + IMR − MMR)`（3倍→+32.8%・5倍→+19.5%・10倍→+9.5%・C独立確認値と一致）。ただし**funding反転で証拠金が先に枯渇する経路も上記日次勘定で捕捉**（価格未到達でも funding払いで清算しうる）。

### 4-3. 追証（マージンコール）ロジック（2方式を並記）
デルタニュートラルの「中立」が離散清算で崩れる機構（prescreen §テールリスク）を測るため、**2方式を並記**する:
- **方式I（分離証拠金・追証なし・保守／主判定）**: ショートperpレッグの証拠金が枯渇したら**当該レッグは清算＝差し入れ証拠金（1/L）を離散的に全損**。現物ロングの含み益は**清算時点で実現されず**、清算後に**現在価格でデルタニュートラルを再構築**（再エントリー＝4レッグ往復コストを控除）。＝prescreenが警告した「現物ロングの含み益と相殺される前にレッグが飛ぶ」離散イベント。**主判定はこの保守側（方式I）**。
- **方式II（クロス証拠金・現物益で追証・楽観／参考）**: 現物ロングレッグの含み益を証拠金に振替（同一取引所・クロスマージン相当）できると仮定し、現物益が続く限りショート清算を回避。＝「連続時間で中立が保たれる」楽観ケース。**参考併記のみ・採否判定には使わない**（実運用の資金移動遅延・取引所リスクを織り込めないため）。
- 両方式の**清算イベント数・清算日・離散損失額・再構築コスト**を各テール窓・連続期間・BTC/ETH・レバ帯別に出力。

### 4-4. 「真の」被害幅の算出（C条件B）
方式I（主判定）の日次スリーブ純P&L（連続MTM＋離散清算損＋再構築コスト＋funding受払＋反転往復コスト＋資本コスト）から、**離散清算損を含む真の被害幅**を算出:
- 累積ネットP&L・**真の最大DD**（G0-4下限値235/166bps等と対比）・最悪日次損失・清算イベント数。
- **資本コスト**: ショートperp証拠金（1/L × 名目）× **年率4%**（Stage0前提・無リスク金利相当の機会費用・「Stage0固定前提」と明記）を日次控除。

## 5. CVaR基準のポジションサイジング（Sharpe基準Kelly禁止・回す前に数値固定）

prescreen §Kelly警告・C条件Aに従い、**サイジングはボラ/SharpeでなくCVaR（テール・最悪シナリオの被害幅）基準**とする。損益分布は左に太いテール（平時小益＋稀に大損）ゆえSharpe基準Kellyは過剰レバの温床＝**禁止**。

### 5-1. CVaRの定義（固定）
- **CVaR水準＝97.5%**（＝最悪2.5%の日次損失の期待値＝Expected Shortfall）。§4方式Iの**離散清算損を含む**日次スリーブ純P&L分布から算出（**テール窓T1/T2/T3を含む連続期間全体**を母集団とする＝テール込みのCVaR）。

### 5-2. サイジングルール（固定・回す前に数値確定）
各レバ帯 L・銘柄について、スリーブへの資本配分比率 `w`（配分資本に対するグロス名目倍率）を以下で決める（**フラクショナルCVaR＝保守側**）:
- **リスク予算（固定）**:
  1. **日次CVaR_97.5（テール+清算込み）損失 ≤ 配分資本の 2.0%**。
  2. **最悪単一テール窓の累積損失（清算込み）≤ 配分資本の 20%**。
  3. 上記2条件を満たす最大 `w` に対し**フラクション f=0.5 を掛ける**（CVaR中立水準の半分でサイズ＝保守）。
- 結果として得られる **`w*`（持続可能なサイズ）・その `w*` での年率ネットキャリー** を各レバ帯・銘柄で報告。
- **⚠ 禁止**: Sharpe/ボラ基準のKelly・フラクショナルKelly、CVaR水準やリスク予算やfを結果を見て変える行為、5倍/10倍の高利回りを理由に採用へ選ぶ行為。リスク予算（2%/20%/f=0.5）・CVaR水準（97.5%）は**本specの固定値**。

### 5-3. サイジングの位置づけ
- CVaRサイジングは**Stage 1-B**でパイプライン統合として測定。net Sharpe は**報告するがサイジングには使わない**（あくまでCVaR基準）。net Sharpe は「グロス陽性/ネット陰性の罠」（OBS025/030型）検出の参考指標として併記。

## 6. 段階的評価（Stage 1-A → 1-B → 1-C。前段通過が後段の前提・予測単位とパイプライン両方を測定）

### Stage 1-A — 予測単位（ネットキャリー期待値・テール込みで有意にプラスか）＝最初の関門・kill判定
「キャリーのネット期待値がテール込みで有意にプラスか」を測る（**C条件・kill基準の予測単位相当**）。**清算・レバ・CVaRサイジングは含めない**（純粋なキャリー期待値＝予測単位）。§2の等ノーション・W=7シグナルで、日次ネットキャリーP&L列を構築（**BTC・ETH 各々独立に**）:
- **日次ネットキャリーP&L_t** = funding P&L_t（W=7方向・受払）＋ ベーシスP&L_t（実perp）− 反転往復コスト（反転日のみ・BTC24.064/ETH24.224bps）− 日次資本コスト（等ノーション前提の名目基準・年率4%相当）。
- 出力（生数値・銘柄別・**連続全期間＋T1/T2/T3＋calm＋前半/後半2分割**）: 日数n・累積ネットP&L(bps)・平均日次(bps)・年率ネット利回り(%)・**block-bootstrap p値**。
- **統計的有意性（permutation/bootstrap・030/031のpower0バグ回避）**: H0: 日次ネットキャリー平均 ≤ 0。**stationary block bootstrap（ブロック長=7日＝Wと整合・N=5000・seed=20260705）で平均0中心化リサンプリング**し、観測平均以上が出る頻度をp値とする。**⚠ 固定集合の単純シャッフル（平均不変＝OBS030/031で名指し警告のpower0バグ）を使わない**（リサンプリングが平均を動かせる方式であることをBが自己点検・生ログに記録）。
- **G1A（採用の必須前提・未達なら即打ち切り）**: **連続全期間**で、**BTC・ETH の両方**が `平均日次ネットキャリー > 0` **かつ** `bootstrap p < 0.05`、**かつ** どの単一テール窓T1/T2/T3も連続全期間の累積ネットを負に転じさせない（テール込みで期待値が生存）。
  - **G1A未達（いずれかの銘柄が未達 or テール1窓で全期間が負転） → 本実験は打ち切り**（Stage 1-B/1-Cに進まない）。＝テール込みでネットキャリー期待値が有意にプラスと言えない＝026の平時楽観がテールで崩れる。限定棄却（銘柄BTC/ETH・期間2019-2026・取引所Binance代理・構成=現物×perp・W=7を明記＝キャリー全般の一般化棄却にしない・029/030の教訓）。

### Stage 1-B — 清算シミュ込みスリーブ（CVaRサイジング・真の被害幅）＝パイプライン統合・kill判定
G1A通過を前提に、§4の清算シミュ（連続保有・mark基準MTM・証拠金勘定・funding反転枯渇・方式I主/方式II参考）を**レバ帯 L∈{3,5,10}・BTC/ETH別**に回し、§5のCVaRサイジングを適用。

- **G2B（パイプラインが破綻していないことの必要条件・kill）**: **最低レバ帯3倍**で、**BTC・ETH の両方**において、CVaRサイジング（リスク予算2%/20%/f=0.5）を満たす `w* > 0` が存在し、かつ **`w*` での年率ネットキャリーがプラス**（テール+離散清算損+全コスト控除後）。

### Stage 1-C — ②との合成（採用の主ゲート＝ポートフォリオ限界寄与・PJ000001 5.4）

  - (b) **合成DD削減**: 凍結ウェイト合成の確認期間 最大DD − ②単体 最大DD **≤ −5pt**（5ポイント以上削減）、かつSharpeが②単体比 **−0.05 を下回って悪化しない**。

### 採用 / 不採用（回す前に確定）
- **採用（候補・バックテスト条件）**: **G1A かつ G2B かつ G3C かつ G4C** を満たす（G1A/G2BはBTC・ETH両方・3倍・テール込み）。

## 7. 選定 / 確認プロトコル（過学習の炙り出し・A設計判断）
