**総合＝分岐(a) 保留・司令塔上申。** spec §4 の**最優先の分岐規則**（「**G0-E1 が E1-POSITIVE の場合、他のゲートの達成度によらず、総合＝分岐(a)**」）が発動する。G0-E1 は **E1-POSITIVE**（`btc_usdc` 系列の最小ロット2脚vega `V_min` = 0.9281598 USD/vol pt ≤ (1/3)×9.281539 = 3.093846）に**一意に**当てはまる。したがって **Stage 1（必須条件A/B）へ自動進行してはならない。**

**補助的にも同じ結論に写る**: 仮に最優先規則が無かったとしても、GO条件は「G0-E1 = E1-NEGATIVE または E1-PARTIAL」を必須とするため成立せず、かつ G0-C2／G0-C4／G0-C5 が部分達成であるため、最良でも分岐(b)止まりであった。

**⚠ ただしCとして、この「分岐(a)」は「BTCのまま粒度が解けた（＝救世主が見つかった）」ことを意味しない。** 本判定書の核心は以下の3点であり、司令塔はこの3点をもって判断されたい。

1. **`btc_usdc`（USDC決済・線形・`min_trade_amount=0.01`）は、商品規格としては本物である。** 最小ロット必要資本は BTC標準 $46,652.77 に対し **約 $4,610**（1/10）。BTC原資産ゆえ VRP系列・|CVaR| は BTC標準と同一であり、**テール1単位あたりプレミアム 0.19713 を保ったまま粒度だけが1/10になる**。同一スナップショットでの**気配ベースの往復コストも BTC標準とほぼ同一**（C独立再計算: btc_usdc 2.5587 vs btc_usd 2.5715 vol pt/週）。ETH乗り換え案（テール単位プレミアム 0.07967＝BTCの40.4%）を、この一点において厳密に上回る。
2. **しかしその「本物さ」は、規格と気配までであって、約定実績では一切裏付けられていない。** D5が選定した代表満期地点（`BTC_USDC-7AUG26-64000-C/P`）は `include_old=true` で**過去全期間の約定0件**、建玉 call 0.02／put 0.1枚。系列全体（550銘柄）の24h出来高は **$34,089.80** で、**BTC標準ATM 2銘柄だけの $55,486.34 を下回る**。板の気配は存在するが、その気配が実弾で執行できるかは**スナップショットからは原理的に検証不能**である。
3. **ETH案の経済的優位は、Stage 1のキルゲートを回すまでもなく、Stage 0の時点でほぼ消滅した。** prescreen §5-3 の「必要資本 1/19.6」は**二重の誤りで、実測は 0.4933（約1/2）**（誤り①: ETHの `min_trade_amount` は実測 **1枚**であり0.1枚ではない＝10倍の誤り。誤り②: BTCの `vegaNotionalPct` を流用しており、ETH固有値では1.69倍不利）。一方でテール単位プレミアムは 0.404 倍（prescreen概算の0.42〜0.47よりさらに悪い）。**すなわち実際の取引条件は「最小ticketが半分になる代わりに、資本効率が4割になる」であり、prescreen が想定した「資本95%減の対価として収益45%減」という交換条件は成立していない。**

### E1-2. 【C独立検証】vega単位の妥当性 — spec の物理サニティは**この系列対では退化しており情報を持たない**

**指摘（A設計チームへの申し送り）**: spec §3-1 step5 の物理サニティ `|(V_min(cand)/V_min(btc標準))/(名目比×√残存比) − 1| ≤ 0.20` は、**候補とBTC標準が同一原資産・同一満期（2026-08-07）・同一strike（64000）である本ケースでは、恒等式に退化する**。実際、per-contract vega は 46.40793（USDC線形）と 46.40756（BTC逆数）で一致しており、名目比 0.100001 は結局 `min_trade_amount` 比 0.01/0.1 に index価格比（≈1.00001）を掛けたものにすぎない。**diffAbs=5.4e-6 という「誤差0.0005%」は、単位換算が正しいことの証拠ではなく、分子と分母が同じ仮定を使っていることの帰結である。** spec が意図した「linear/reversed で vega の単位系が異なりうる」というリスクを、この検定は**一切検出できない**。

**そこでCが独立に裏取りした**（Black-Scholes による第一原理チェック）:
- BTC標準 ATM call: S=64489.33, T=12.186/365=0.033386, √T=0.182718。ATM近傍で φ(d1)≈0.399。
- 理論 vega（1 vol pt = 1%あたり）= S·φ(d1)·√T/100 = 64489.33 × 0.399 × 0.182718 / 100 ≈ **47.0 USD/vol pt/契約**
- 実測 = 46.4076（BTC標準）／46.4079（BTC_USDC）→ **理論値と 1.3% 以内で一致**

**→ `ticker.greeks.vega` が linear/reversed いずれでも「1契約あたり・1 vol pt あたり・USD建て」であるという B の前提は、Cの独立検証により支持される。** よって `V_min` 比 1/10 は本物であり、E1-POSITIVE の分類は単位換算の誤りに由来しない。

### E1-3. 【C検出・重大】候補系列の `C_options` に単位バグ — 生データが使用不能

`scripts/probe-deribit-instrument-inventory.ts` L278-279:

```ts
const callPremiumUsd = call.markPrice * indexPrice;
const putPremiumUsd  = put.markPrice  * indexPrice;
```

この式は inverse（`btc_usd`・markPriceがBTC建て）にのみ妥当であり、**linear（`btc_usdc`・markPriceが既にUSDC＝USD建て）に適用すると index価格倍（≈64,490倍）に膨らむ**。半スプレッドも同様に `× indexPrice` されている。結果:

- 生データ `vMinBySeries[btc_usdc].economics.C_options_volpt` = **97,275.167 vol pt/週**（BTC標準は 1.876）
- `callPremiumUsd` = **$126,962,929.98**（BTCオプション1枚のプレミアムが1.27億ドル＝物理的にあり得ない値）

**spec §9-9 は「完了報告の前に、生成した成果物ファイルが実在し、中身が空でない（NaN/Infinity/null埋めでない）ことを自分で確認してから報告すること」を義務づけている。** 本値は NaN でも Infinity でもないため C5-3 の字義は通るが、**桁が5オーダー外れた値を自己点検で捕まえられていない**（031で3回連続発生した「実行完了を自己確認せず完了報告する癖」の変種）。

**Cによる正しい値（`btc-usdc-liquidity.json` の同一スナップショット 2026-07-26T04:02Z・満期8/07・strike 64000 から独立再計算）**:

| 系列 | 手数料/脚 | 半スプレッド call/put | 1ラウンド計 | 2脚vega | **`C_options`（vol pt/週）** |
|---|---|---|---|---|---|
| `btc_usdc` | $19.343 | $40.00 / $40.00 | $118.685 | 92.7685 | **2.5587** |
| `btc_usd`（標準） | $19.343 | $32.238 / $48.357 | $119.280 | 92.7695 | **2.5715** |

**→ 気配ベースでは、候補系列の往復コストは BTC標準と実質同等（むしろわずかに安い）。** これは司令塔判断に直結する数字であり、B の成果物には**正しい形で存在していない**。なお手数料は `min(0.0003×index, 0.125×premium)` の第1項が binding のため、プレミアムのバグの影響を受けず偶然正しい。

### L-4. 【OBS000038型の罠に該当するか】— Cの判断: **同型の構造を持つが、falsifyされてはいない。「未証明」である**

- **同型である点**: 「単一の魅力的な指標（`V_min` が1/10）だけが合格し、書物全体（実際に執行して収益が残るか）が未検証」という構造は、OBS000038（条件付き相関だけ合格→アンサンブル全体では逆効果）と**同じ形**である。この一点をもって「BTCの資本の壁が解けた」と宣言すれば、それは同じ罠に落ちる。

- **→ Cの結論**: 「規格としては1/10だが実質流動性は薄い」を理由に**E1-POSITIVEを取り消すことはしない**（それは基準を事後に動かすことになる）。代わりに、**分岐(a)の上申において「規格の存在＝執行可能性ではない」ことを一級の未解決論点として明示し、決着方法（＝実弾での極小ロット約定テスト）を司令塔に提示する。**

3. **【保留】Stage 1（必須条件A/B）への進行は保留を推薦。** 理由: ETH案の経済的優位（prescreen が「唯一かつ本物の価値」と呼んだもの）が Stage 0 の実測で 1/19.6 → 0.4933 に縮み、かつ価格比レジーム依存であることが判明した。この状態でStage 1の確認期追試（それ自体が中〜低の事前確率）にリソースを割く合理性は低い。**ただし、`btc_usdc` が実約定不能と判明した場合には、ETH案は依然として唯一の残存選択肢であり、その時点でStage 1へ進む価値が復活する。**
