## 1. 仮説（1文）

**BTC VRPで実測された資本粒度の壁（CVaR整合サイジング `vegaNotionalPct = 0.5×(0.02/|CVaR_w|)` に対し最小発注単位0.1枚の必要資本が $44,694 と粗すぎ、数百万円規模ではf=0.5を守れない）は、(i) Deribit上に「BTC原資産のまま最小ロットvegaがより小さい商品的手段」が存在するならETHへ乗り換えずに解け、(ii) 存在しない場合に限り ETHオプションでVRPを表現する道が検討に値する——そしてこの (i)/(ii) の分岐と、その後の比較に耐える「BTCとETHを同一定義・同一時刻で測った数値」は、Stage 0のオフライン計算だけで確定できる。**

### 2-1. 【A設計チームの設計判断】ETH週次グリッドのアンカーを 2021-03-24（BTCと同一）に固定する

- **主系列（判定・永続化・以後の全Stageの入力）＝ アンカー 2021-03-24 の非重複7日グリッド**。ETH DVOLの実起点が 2021-03-24 より後の場合は、**2021-03-24 と同位相（日数差が7の倍数）となる最初の日付**を開始点とする（位相を崩さない）。
- **理由**: (i) 必須条件A（Stage 1）のETH-BTC週次VRP相関は**同一週境界でペアが組めなければ測れない**。(ii) 必須条件B（Stage 1）の「BTCと同一の選定/確認分割」は、週境界が揃って初めて同一の切り方になる。(iii) prescreen が禁じた「切り口を変えて数字を良く見せる」余地を最初から潰す。
- **参考系列（開示のみ・判定に使用禁止）＝ ETH DVOL実起点をアンカーとする系列**（ワンオフ実装と同じ切り方）。両系列の n と平均VRP を並置出力し、切り方による差を可視化する。
- **⚠ ワンオフ実測の「n=278週・平均VRP +10.4774」は参考系列側の数値であり、本Stage 0以降の判定には一切使わない。** 判定に使うのは主系列（2021-03-24アンカー・リポジトリに永続化された生データ）のみ。

### 2-2. ATM選定のフォールバックを禁止する（ワンオフ実装からの明示的な変更点）

`scripts/vrp-eth-reference.ts` は「|delta|∈[0.35,0.65] の候補が代表満期に1つも無い場合、index最近接strikeを素朴ATMとして採用する」フォールバック（`nearestStrikeFallback`）を持つ。**Stage 0ではこれを禁止する。**

- **代表満期（残存≥7日で最近接）に |delta|∈[0.35,0.65] の候補が存在しない場合、代替選定をせず、その事実（全候補のstrike/delta一覧・ticker取得診断）を生データとして記録し、A設計官・Sへ差し戻す。**
- 理由: フォールバックはBTCとETHで**異なる選定規則**を適用することを意味し、「方法論の同一化」という本Stage 0の目的そのものを破壊する（かつdelta条件を外した脚はvegaが系統的に小さく出て必要資本を過小に見せる方向のバイアスを持つ）。
- 参考: prescreen §5-1 は 2026-07-26 のETHスナップショットで**フォールバック不使用の正規の方法で成立**（strike 1900・delta 0.4656）と記録している。ゆえに禁止による実害の見込みは低い。

## 3. Stage 0 の合否ゲート（回す前に基準を固定・判定はC品質チーム）

### 3-1. G0-E1: Deribit商品規格インベントリ ＝ **最優先・単独の分岐ゲート**

**位置づけ**: prescreen §8-3(ii)「**(ii) は本テーマより明確に優先度が高く、かつ数分で確認できる。A設計チームはStage 0の最初にこれを置くこと**」。**このゲートが肯定的なら、本テーマ（ETHへの乗り換え）の要否そのものが変わる。** ゆえに他のどのゲートよりも先に実行し、結果によって総合判定を上書きする（§4の最優先規則）。

**調査手順（B実装官が実施・すべて実レスポンスを正とする）**:

1. `GET /public/get_currencies` で Deribit が配信する全通貨コードを**実測列挙**（推測でBTC/ETHに限定しない）。
2. 各通貨コードについて `GET /public/get_instruments?currency={CCY}&kind=option&expired=false` を実行（`currency=any` が受理されるかも実測し、受理されるならそれも併用）。**加えて `kind=future`（perp含む）も列挙**（デルタヘッジ手段の存在確認のため）。
3. 各 option instrument について、以下のフィールドを**そのまま**記録する: `instrument_name` / `kind` / `instrument_type`（linear/reversed 等） / `base_currency` / `quote_currency` / `settlement_currency` / `counter_currency` / `price_index` / `contract_size` / `min_trade_amount` / `tick_size` / `taker_commission` / `maker_commission` / `expiration_timestamp` / `strike` / `option_type` / `is_active`。**フィールドが存在しない場合は「API非配信」と明記**（推測で埋めない）。
4. **「BTC原資産」の判定基準（回す前に固定）**: `price_index` が `btc` で始まる **または** `base_currency == "BTC"`。この基準で全 option instrument を BTC原資産 / ETH原資産 / その他 に分類し、**系列（series）＝ `(price_index, settlement_currency, contract_size, min_trade_amount)` の組**でグルーピングして系列一覧を出力する。
5. **各BTC原資産系列について「最小ロット・ストラドルvega」を実測する**:
   - D5（残存≥7日で最近接expiry）・D6（|delta|∈[0.35,0.65] の index最近接strike・**フォールバック禁止**）でATMストラドルを選定。
   - `ticker.greeks.vega` を call/put 両方取得し、**最小発注ロット1つ分の2脚合計vega（USD/vol pt）** `V_min` を算出する。
   - **⚠ 単位換算の明示義務**: `ticker.greeks.vega` の単位（1契約あたりか、1原資産単位あたりか、USD建てか）は系列規格（inverse／linear）で異なりうる。**B実装官は、`contract_size`・`min_trade_amount` と公式ドキュメントから単位の導出過程を出力に明記すること。API＋公式ドキュメントから単位が一意に確定できない場合は、推測で換算せず事実を記録してA設計官へ差し戻す。**
   - **物理サニティ（回す前に固定）**: 候補系列とBTC標準系列の間で
     `|( V_min(cand) / V_min(btc標準) ) / ( 名目比 × √(残存日数比) ) − 1| ≤ 0.20`
     （名目比 ＝ `contract_size×min_trade_amount×index_price` の比）。この範囲内なら「vegaは名目×√残存に比例するという理屈と整合」と事実記録する。**0.20を超える場合は単位換算誤りの可能性として事実を記録し、独自の補正をせずA設計官へ差し戻す**（S が prescreen §5-1 で BTC/ETH について行った独立検算と同型の点検）。
6. **候補系列の経済性を同一手続きで測る（開示・Stage 0では採否判定しない）**: 候補が存在する場合、その ATM ストラドルについて D7〜D9 で `C_options`（vol pt/週）を算出し、`best_bid`/`best_ask`/`open_interest`/`volume`（`ticker` で取得可能なもの）を併記する。**BTC原資産である限りVRP系列・|CVaR| はBTC標準と同一**（同じDVOL・同じRV）であるため、`vegaNotionalPct` はBTC標準の値を用いて必要資本を算出してよい（この前提を meta に明記）。

**分類基準（回す前に固定・結果を見て選ばない）**:
`V_min(btc標準)` ＝ 同時点スナップショット（§3-4 G0-C1）で実測したBTC標準系列の最小ロット2脚vega（参考: OBS000037 Stage 2 の 2026-07-13 値は 2脚vega 89.76208 × 0.1枚 = **8.976208 USD/vol pt**、必要資本 $44,693）。

| 分類 | 条件（回す前に固定） | 意味 |
|---|---|---|
| **E1-POSITIVE** | BTC原資産のoption系列で、ATMストラドルが D5/D6 で構成でき、かつ `V_min(cand) ≤ (1/3) × V_min(btc標準)` を満たすものが**1件以上存在** | **BTCのまま粒度を解ける手段が実在**。ETHへの乗り換えより厳密に優れる可能性＝**本テーマ自体の要否を司令塔に上申** |
| **E1-PARTIAL** | 上記を満たさないが、`(1/3) × V_min(btc標準) < V_min(cand) < V_min(btc標準)` の系列が1件以上存在 | 粒度は改善するが限定的。**Stage 2（必須条件D）の比較構成に「第4構成」として追加することの是非をS/司令塔へ上申**（Stage 1は予定通り進む） |
| **E1-NEGATIVE** | BTC原資産のoption系列で `V_min(cand) < V_min(btc標準)` を満たすものが**1件も存在しない** | 「ETH以外に商品的手段は無い」ことを**負の資産として記録**。Stage 1へ進む根拠となる |

- **合否（Cが判定）**: **達成**＝上記4分類のいずれかに、実測データ（全通貨の instrument 一覧・系列グルーピング・候補のvega/単位導出/物理サニティ）をもって**一意に当てはめられる状態**になっている。**部分達成**＝一部通貨で `get_instruments` がエラー/レート制限で完全列挙できず、列挙できた範囲でのみ分類が確定する（未列挙通貨を明記した場合）。**未達**＝`get_currencies`／`get_instruments` が米国IPから取得できず、インベントリを構築できない。
- **⚠ 禁止**: 「BTCには小口商品は無いはずだ」という予断で列挙を省略すること。**全通貨・全 kind=option を機械的に列挙した生データを出力すること**が本ゲートの実質である。

### 3-2. G0-E2: 満期短縮（対抗案2）の開示 ＝ **開示のみ・採択禁止**

- **合否（Cが判定）**: **達成**＝BTC・ETH双方について上記5帯（上場が無い帯は「該当expiryなし」と明記）の表が実測値で埋まっている。**部分達成**＝一方の資産のみ、または一部の帯でATMがdelta band内に存在せず空欄となる（事実を明記した場合）。**未達**＝expiry列挙自体ができない。

## 10. kill基準（チューニング逃避・HARKing・スコープ乗り換えの禁止）

- 本specの事前登録（§2の固定定義／§3の各ゲート基準／§4の分岐規則）の下で未達なら、**基準を緩めず、事実をCへ委譲して停止**する。結果を見てから **アンカー・RV窓長・代表満期規則・ATM定義・delta band・ヘッジ頻度・スリッページ探査名目・CVaR水準・リスク予算・f・E1の1/3閾値・同時性30分・回帰許容差1.0e-4** を調整して再測定してはならない。
- **スコープ内乗り換えの禁止**: G0-E1 が E1-POSITIVE でも、A設計チーム/B実装チームの判断で本テーマを「小口BTC商品の実験」に**その場で書き換えない**。**分岐(a)として司令塔へ上申し、必要なら別OBSを新規起票する**（OBS000031で確立した原則）。同様に、必須条件A で |ρ|<0.3 が出ても4本目スリーブへ昇格させない（Stage 1）。
- **本テーマの「成功」の定義を、ここで明確にしておく**（prescreen §9 の総括を踏襲）: 最も蓋然性が高い結末は「**粒度は解けた。しかしプレミアムは半分以下になり、BTCとの相関は高かった。よってETHは4本目のスリーブではなく、小資本帯でのみBTCの代替となる実装オプションである**」。**この結末は失敗ではなく、実運用に直結する有用な結論である。** 逆に、「ETHが良い」という結論を得るために基準を緩めることは、この実験の価値を破壊する。
