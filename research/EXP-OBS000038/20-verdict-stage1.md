## 総合判定: **STOP（系統廃棄）**

spec §7 の事前固定基準を両方とも**逆方向に**外している。マージナルな未達ではなく、オーバーレイが結合書物のテールリスクを**悪化させた**。エスカレーション条件（ρcarry>0）は非該当のため、保留ではなく確定STOP。B実装チームの生データを独立に再計算し、全数値を再現した上での宣告。

## 根拠（数値・spec §7 当てはめ）

独立再計算（`stage1-weekly-series.csv` の book0_pct/book1_pct から C品質チームが再走）でBの申告値を完全再現:

| 指標 | book0 | book1 | 改善率 | spec §7基準 | 合否 |
|------|-------|-------|--------|-------------|------|
| maxDD | −4.55% | −4.84% | **−6.18%（悪化）** | ≤ book0×0.90（≥+10%改善） | **未達** |
| CVaR95 | −1.65% | −2.09% | **−26.65%（悪化）** | ≤ book0×0.90（≥+10%改善） | **未達** |

- PASS条件は「maxDD ≥10%改善 **AND** CVaR95 ≥10%改善」。**両方とも改善どころか悪化**。片方未達でSTOPのところ、両方が負。
- §5-3 エスカレーション判定: ρ(carry_basisMTM, overlay)点推定 = **−0.277（負）**。>0ではないためエスカレーション非該当 → 保留ではなく**STOP確定**。

## 廃棄理由（G-ensembleが通過できなかった本質的理由）

**予測単位では逆相関ヘッジに見えるが、パイプライン統合ではテールを悪化させる乖離（OBS000025型の罠）。** これがC品質チームが独立に発見した決定的機序:

| 相関の測り方 | corr(book0, overlay) | 解釈 |
|--------------|----------------------|------|
| **stress窓のみ**（BTC≤−8%・20週） | **−0.273** | 予測単位では「ヘッジに見える」 |
| **全期間**（235週） | **+0.062** | パイプラインでは「リスクを足す」 |

- オーバーレイの逆相関ヘッジ性は **BTC週次≤−8% の狭いstress窓に限定**される。しかしmaxDD/CVaR95は**分布全体の最悪5%**で測られ、その最悪週は必ずしもBTC暴落週ではない（VRP自体のボラスパイク週・overlay自前のトレンド逆行週などが混在）。
- 全期間ではoverlayとbook0が**わずかに正相関**（+0.062）。overlayが非stress週に自前のボラ・ドローダウンを持ち込み、書物全体のテールを膨らませる。結果、狭いstress窓で稼ぐヘッジ効果を、それ以外の週の悪化が上回った。
- **ヘッジ性の有無で言えば「stress窓内には存在する（両負）」。しかし規模・作用域が書物のテール支配要因とずれており、パイプラインでは正味マイナス。** spec §4-5の切り分けで言えば「ヘッジ性はあるが、その作用域が書物テールの母集団と一致せず、book1が改善しない」に該当。

これはlab Stage 0が「予測単位（stress条件付き相関）」だけで合格を出し、パイプライン統合の母集団ずれを検出できなかった構造的欠陥の再現である。本プロジェクトが繰り返してきた「予測単位で有望・ポートフォリオ水準で全滅」の罠にそのまま該当。

## 予測単位そのものの脆弱性（追加の負の資産）

STOPに加え、**予測単位（G-tailヘッジ性）の主張自体もlab Stage 0より大幅に減衰・偏在**しており、系統の core命題が過学習気味であったことを示す:

1. **stress条件付き相関がlab値から半減**: ρ(overlay,VRP) = **−0.156**（lab: −0.331）、ρ(overlay,carry) = −0.277（lab: −0.238）。VRP側はlabの半分以下。基差MTM込みの正しい母体で測ると、主張されたヘッジ強度は再現しなかった。

2. **BTC/ETH分解で選定(BTC)/確認(ETH)プロトコルが崩れる（OBS000019型・クロス資産非再現）**:
   - ρ(btc_overlay, VRP) = **+0.0018（実質ゼロ〜正）** / ρ(eth_overlay, VRP) = −0.265
   - VRP脚に対する「ヘッジ性」は**ETH単独のアーティファクト**で、主資産BTCでは消える。spec §3-5が要求する「両資産で独立に負方向」を**VRP側は満たさない**（carry側はbtc −0.373 / eth −0.108で両負）。
   - VRP脚はそもそもBTC基準（Deribit BTC DVOL）であるのに、そのVRPを守るヘッジがBTC overlayでは効かずETH overlayで効くというのは機序として整合性を欠く。片側資産依存の見かけ上のヘッジ。

3. **stress窓がlab(33週)から20週に縮小し「再現」が成立していない**: 共通窓が2021-12-29開始（DVOL律速でなくcarry/overlay履歴律速）でありlab窓と非同一。2020-03 COVID・2021前半crash等の大stress期間が母集団から脱落。ヘッジ性の統計的検出力・再現性がlabより弱い状態での判定である点も、系統の頑健性に対する疑義を強める。

## 実装上の問題点（スクリプト検証で発見）

STOP結論は下記の実装論点に対して頑健だが、記録として残す（PASSであれば下記b・eは差し戻し事由になり得た水準）。

**a. carry会計（§2-2）— 結論: spec記述側に誤り、実装は公式日次定義に忠実**
- 実装は raw spot/perp/funding から `total_pnl_bps = funding_pnl_bps + (spot_return_bps − perp_return_bps)` を再構成。
- C品質チームが公式 `daily-pnl-btcusdt-{T1,T2,T3,calm}.csv` と突合 → **総365重複日で平均乖離0.047bps・最大7.9bps（断片初日の価格リターン0埋めに起因、再構成側がより連続的で正しい）**。公式CSVの `total_pnl_bps` 自体が `funding + basis` の定義（コスト非内包）であり、実装はこれに忠実。
- 公式daily-pnl CSVは**stress断片365日のみ**で全期間を張れない。再構成系列2492日は sanity anchor（BTC≈2493日）と一致。よって再構成は必然かつ妥当。
- ただし spec §2-2/§2-3 は「total_pnl_bps はコスト内包」「reversal 24bps・capital cost をそのまま踏襲」と記載しており、**実際の公式CSVはこれらを日次total_pnl_bpsに含んでいない**（別層で適用）。data_notesの「no capital cost, no reversal cost, no signal flip」は事実。**spec記述と実データの齟齬**であり設計チームへ申し送るべき点。ただしこれらは book0/book1 双方の carry脚に等しく効く純ドラッグであり、overlay増分（=STOP根拠のbook1−book0差分）には非本質的。static cash-and-carryにreversal/signal flipは本来適用対象外。→ STOP結論に影響なし。

**b. VRP整合確認 n_matched=1 は検証力ほぼゼロ（循環的）**
- `stage1-vrp-prediction-unit.json` の weeklyPoints をそのまま使用（外部APIブロックのため独自Deribit再構成ではない）。整合確認は forward ledger の `is_cohort_anchor=1` 行1点（2026-07-11）のみ、diff=4e-17。
- これは**同一の vrp値に同一式（C_real/vega）を当てて自明に一致**しているだけで、再構成ロジックの独立検証になっていない。spec §2-1の要求は形式的には満たすが実質的な突合検証力はない。フォワードledgerの anchor行が少数という制約による。

**c. 週次サンプリング（7倍罠）: 問題なし** — VRP weeklyPoints n=277（2021-03〜2026-07 ≈ 274週）で週次1点、carry/overlay は各アンカー [t+1,t+7] 非重複複利。Σ全行過大計上なし。

**d. 先読み: 問題なし** — book0 vol・overlay σ は `.shift(1)` 済、σ推定は [t−90, t−1]、overlay実現は [t+1, t+7]、TSMOMは t価格でシグナル→翌日適用。PITクリーン。

**e. Windowアライメント（§2-0/§8-3）— 金曜アンカー逸脱（実害限定）**
- 全アンカー日が **Wednesday**（例: 2021-12-29, ..., 2026-06-24）。spec §2-0/§8-3が凍結した「金曜終値アンカー」を逸脱（VRP weeklyPointsの曜日を継承）。
- ただし**3脚すべてが同一Wednesdayアンカーで相互整合**しており、spec §8-3が警告する「曜日不一致による見かけ上の相関劣化」は生じない（cross-leg整合は保たれている）。凍結パラメータからの逸脱ではあるが、判定結論への実害は限定的。

**f. a係数: 正しい** — a = √(0.15/0.85) = 0.42008。realized_rc_overlay = 0.132（target 0.15にやや不足だが、寄与が想定より小さい＝overlayの悪影響がむしろ控えめに出る方向）。

**g. HARKing: なし** — 全パラメータ凍結（C_real/vega/a/vol_target/σ窓/lookback）、事後変更なし。confirmation run。スクリプト確認済み。

## 採用不可の負の資産（次につながる知見）

1. **「予測単位の条件付き相関」だけでヘッジ系統を合格させてはならない（最重要）。** stress窓corr=−0.273 は魅力的に見えるが、全期間corr=+0.062 でパイプラインは死ぬ。ヘッジ系統の評価は**必ず書物テール（maxDD/CVaR）の実測**で確定し、条件付き相関は補助診断に留める。lab Stage 0のG-tail合格は予測単位過信の典型で、Stage 1のパイプライン実測がそれを覆した。マルチステージ設計（lab予測単位→本POCパイプライン）が正しく機能して偽陽性を捕捉した好例。

2. **TSMOMオーバーレイの「共有テール打ち消し」は作用域が狭すぎる。** ヘッジ効果はBTC≤−8%のslow-trend crash窓に限定され、書物の最悪5%を支配する非BTC-crash型テール（VRP自体のボラスパイク等）には無力どころか自前ボラで上乗せする。spec §6-1の既知弱点（速いV字gap非ヘッジ）に加え、「遅い下落窓以外の書物テールを悪化させる」という新たな守備範囲外が判明。テールヘッジは**書物の実際の最悪週の駆動要因に作用域を合わせて設計**する必要がある（当てずっぽうのTSMOMではなく、VRPボラスパイク連動やオプション明示ヘッジ）。

3. **G-tailヘッジ性のクロス資産非再現。** VRP脚（BTC基準）に対するoverlayヘッジがBTCで≈0・ETH単独依存。片側資産アーティファクトのヘッジは機序整合性を欠き、本番で剥落するリスクが高い。lab Stage 0のρ(VRP)=−0.331は窓依存・ETH偏在の可能性が高く、過大評価だった。

4. **基差MTM込みでも救済されなかった。** Stage 0のG-ensemble不合格（7.7%/6.5%）はlab carryの基差MTM欠如が主因と仮説されたが、正しい基差MTM込み母体で測ると改善は**プラス側にすら来ず（−6.2%/−26.7%）**、むしろ悪化。基差MTM欠如は不合格の主因ではなかった。SYS-012（12a TSMOMオーバーレイ）はここで系統廃棄が妥当。

5. **設計チームへの申し送り**: spec §2-2/§2-3のcarry会計記述（total_pnl_bpsがコスト内包・reversal/capital踏襲）は実データ（公式daily-pnl CSVはfunding+basisのみ）と齟齬。今後SYS-012派生や他系統でOBS000032 carryを母体に使う際は、コスト適用層の正確な定義を spec に反映すること。またstress窓の共通窓律速（DVOLでなくcarry/overlay履歴が律速で2021-12-29開始・20週）を前提に、lab 33週との非同一を織り込んだ検出力設計にすること。
