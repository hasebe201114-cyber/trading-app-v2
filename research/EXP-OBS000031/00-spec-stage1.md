## 1. エッジの事前登録（1つに固定・多重検定回避）

- **登録エッジ＝ microstructure mean-reversion（短期の過剰反応の反転）ただ1つ。**
- **路線α（日足モメンタムの短時間足縮小）は本実験では測定しない**（順張り版・モメンタム縮小版を並走させない）。理由: prescreen の通り、4hモメンタムと日足モメンタムは同一トレンドの解像度違いで信号間相関が高く、独立ベットが増えない＝**OBS000028の非独立性の再演**。実効ブレッド不変×コスト線形増で期待値悪化側。よって順張り版は**実装しない**。
- 平均回帰以外（清算反発・日中季節性・モメンタム縮小）を試したい場合は、本実験のリスコープ（結果を見てからの乗り換え）ではなく**別OBSの新規起票**でのみ許可する。

## 2. 確定粒度＝ **1時間足（1h）に固定**（HARKingでない客観的理由）

3粒度すべてが2022をカバーする（Stage 0）ため、**成績を見て選ぶことはできない（＝HARKing）**。以下の**シグナル成績と無関係な構造的・コスト論的根拠のみ**で1hを事前確定する:

1. **ブレッド目的（頻度軸の本旨）**: 本テーマは `IR≈IC×√ブレッド` のブレッドを頻度で増やすもの。1h＝24本/日（≒8,760本/年）で、日足②の年間ベット数（≈30〜40）に対し桁で多い独立機会を与えつつ、時系列OOSの統計力も十分確保できる。
2. **コストハードルの実現可能性（本テーマ最重要）**: 往復コスト ≈12〜13bps（テイカー・Stage 0確定）。ネット陽性には1トレードのグロス反転期待値がこのハードルを超える必要がある。**15m** は数本の値幅が小さく（バー値動きがコストハードルに対し相対的に小さい）ネットが原理的に厳しい上、回転率が桁で増え年間ドラッグが膨張。**4h** は6本/日で日足②に対する頻度ブレッドの上乗せが薄く、かつ保有ホライズンが日足モメンタムの時間帯に重なり②との相関が上がりやすい（低相関KPIに不利）。**1h** は、1バーのボラティリティがコストハードル（12〜13bps）を超え得る大きさを持ちつつ回転率が抑制され、かつ保有ホライズンが日足②と構造的に分離する（低相関KPIに有利）——3粒度のうちこの3条件を同時に満たすのは1hのみ。
3. この選定は**Stage 0の深度事実＋確定コスト＋②との構造的距離のみ**に基づき、シグナルのIC/Sharpeを一切参照していない（HARKing非該当）。

**→ 確定粒度＝1h。4h/15mはStage 1スコープ外。** 別粒度を試すのは本実験のリスコープでなく別OBS。

## 3. シグナル定義（固定・可変にしない・1パラメータセット）

対象＝`BTCUSDT` / `ETHUSDT` の **1h終値**（Stage 0 の `fetch-bitget-intraday.ts` で取得した1hOHLCV。UTCで連続）。全パラメータを本specの値で**ハードコード**し、グリッド探索を禁止する。

- **形成ルックバック K = 3 本**（＝過去3時間の累積リターン）。
  `rK[t] = close[t] / close[t−K] − 1`
- **ボラティリティ正規化窓 W = 168 本**（＝直近7日＝168時間）。**t−1 までの過去バーのみ**で `rK` の標準偏差 `σK[t]`（先読み排除・rolling、tの値は含めない）を算出。
  `z[t] = rK[t] / σK[t]`
- **エントリー閾値 Z_enter = 2.0**（過剰反応＝2標準偏差超の一過性ムーブをフェード）。
  - `z[t] > +2.0` → **SHORT**（上げ過ぎをフェード。position = −1）
  - `z[t] < −2.0` → **LONG**（下げ過ぎをフェード。position = +1）
  - 帯内（|z|≤2.0） → ノーポジション
- **保有本数 N = 3 本**（＝3時間で反転を取り、時間ベースで無条件イグジット）。**イグジット閾値という追加自由度は設けない**（時間イグジットのみ）。
- **非オーバーラップ**: 時刻tでエントリーしたら **t+N まで新規エントリーしない**（ポジション1本のみ・重複させない）。これにより**独立ベット列**を得る（permutation検定の妥当性・オーバーラップによる見かけ有意化の排除）。信号が連続発火してもオープン中は無視。
- **サイジング**: 予測単位・スリーブともに **等ノーション固定**（Kellyサイジングは持ち込まない・029準拠）。スリーブの参照名目＝**$50,000**（Stage 0でコスト実測した中位ティア）。
- **Lグリッド・Z帯・K・W・N の探索は行わない。** 参考診断として選定期間のみで別値を併記することも**しない**（自由度を作らない）。

## 4. ネットコストの組み込み（本テーマ最重要・グロス判定禁止）

Stage 0確定の執行コストモデルを用い、**ネットコスト後を主ゲート**にする。

- **往復コスト（1トレード＝エントリー＋イグジットの1回転）**:
  - **主モデル（S-taker・保守アンカー）**: 銘柄別に Stage 0確定値 @ $50k名目を固定使用＝**BTC 12.03bps / ETH 12.69bps**（1回転あたり）。**主ゲートはこのS-takerで判定する。**
  - 副モデル（S-maker・参考）: BTC 8.02bps / ETH 8.34bps（指値約定率50%悲観）。**採否判定には使わず**、生数値として併記。
  - 感応度（参考併記）: $100k名目のS-taker（BTC 12.13bps / ETH 13.06bps）でも再計算し、サイズ増でネットが崩れないかを開示。
- **Funding の扱い**: 保有N=3本（3h）は Bitget のfunding決済間隔（8h）より短く、多くのトレードは決済を跨がない。**主ネットモデルはfundingを除外し、往復執行コストのみを引く。** これは**やや楽観側（1トレードあたり <1bp の過小）**であることを明記（コスト過大の二重計上分＝§0申し送りと相殺方向・実害は往復12bps台に対し無視可能）。
- **1トレードあたりグロス期待値のコストハードル判定（最初の確認）**: Stage 1-A で **平均グロス往復リターン（bps）**を出力し、**S-taker往復コスト（BTC 12.03 / ETH 12.69 bps）を超えるか**を最初に確認する（prescreen: グロス期待値がコストハードルを超えなければネットは原理的に負）。
- **年間コストドラッグの明示**: `年間ドラッグ = 年間トレード数 × 往復コスト(bps)` を銘柄別に出力する（回転率×往復コストの可視化・prescreen必須）。

## 5. 選定 / 確認プロトコル（過学習の炙り出し・クロス資産の扱い）

**設計判断（A設計官）**: 本エッジのパラメータ（K/W/Z_enter/N/粒度）は**理論から事前確定しており、データにフィットさせない**。したがって「チューニング用に一方の資産を選定に割く」必要がない。よって:

- **クロス資産＝BTC/ETH の両方を独立確認トラックとして扱う**（片方を選定用に予約しない）。理由: 選定でのパラメータ最適化がゼロなので、**両銘柄をそれぞれ独立の未見確認**に使う方が、単一資産の偶然（019/028で単一資産の過学習を炙り出した武器）を強く排除できる。**エッジは BTC と ETH の両方で成立して初めて認める**（片方のみ成立＝単一資産の偶然として不採用扱い・勝った側だけ採る＝HARKing禁止）。
- **時系列分割を第一のOOSにする**（単一資産クラスゆえ held-out銘柄OOSは使えない・prescreen）。**平均回帰の生死は「持続トレンド局面（＝2022弱気）で轢かれるか」であるため、2022弱気を確認（OOS）側に配し、逆境レジームでのOOS頑健性を採否ゲートで直接試す。**

### 期間の厳格分離（回す前に固定・日付レンジ）
- **選定期間（in-sample・特性把握と凍結ウェイト算出のみ）**: **2019-08-10 00:00 UTC 〜 2021-12-31 23:59 UTC**（BTC/ETH 1hが両方存在する起点〜2021末＝強気+レンジ局面）。用途は (i) in-sampleのエッジ有無・レジーム別挙動の把握、(ii) Stage 1-C の②合成用**逆ボラウェイトの凍結**のみ。**シグナルパラメータの調整には一切使わない**（そもそも凍結済み）。
- **確認期間（未見・本判定＝OOS）**: **2022-01-01 00:00 UTC 〜 データ末尾（≈2026-07 UTC）**。選定に一切使わない。**Stage 1-A/1-B/1-C の合否はすべてこの確認期間で判定する。** 2022弱気（平均回帰の逆境）を含むOOSで頑健性を試す設計。
- **確認期間の内部頑健性（縮退検出）**: 確認期間を以下のレジーム窓に分解し、各窓でStageごとのKPIを**生出力**（片一方のレジーム依存でないかをCが叩けるように）:
  - **R-bear（2022弱気・平均回帰の逆境）**: 2022-01-01 〜 2022-12-31。
  - **R-recovery（回復）**: 2023-01-01 〜 2023-12-31。
  - **R-recent（直近）**: 2024-01-01 〜 データ末尾。
  - 加えて確認期間全体を**前半/後半2分割**した各半の Stage 1-A KPI も出力。

## 6. 段階的評価（Stage 1-A → 1-B → 1-C。前段通過が後段の前提）

### Stage 1-A — 予測単位（短期反転の予測可能性）＝最初の関門・kill判定
非オーバーラップのフェード・トレード列について、各トレードの**グロス往復リターン** `gross = position × (close[t_exit]/close[t_entry] − 1)`（t_exit = t_entry + N）を求め、方向的中と有意性を測る。**BTC・ETH 各々独立に。**
- 出力（生数値・銘柄別・選定/確認/前半後半/R-bear/R-recovery/R-recent）: トレード数 n・hitRate（gross>0の割合）・**平均グロス往復リターン(bps)**・グロス年率Sharpe・permutation p値。
- **平均グロス往復リターン(bps) と S-taker往復コスト（BTC 12.03 / ETH 12.69 bps）の対比を必ず併記**（コストハードル判定）。
- permutation: `N_PERM = 5000`、`seed = 20260705`、`momentum-robustness.ts` と同一の並べ替え法（非オーバーラップのトレード列をシャッフルし、平均グロスリターンの帰無分布を作る＝Sharpe不変シャッフルにならないよう**リターン系列そのもの**を並べ替える。OBS000030で検出したSharpe不変シャッフル＝power0の轍を踏まない）。
- **G1A（採用の必須前提・未達なら即打ち切り）**: **確認期間**で、**BTC・ETH の両方**が `hitRate > 50%` **かつ** `permutation p < 0.05`。
  - **G1A未達（いずれかの銘柄が未達） → 本実験は打ち切り（Stage 1-B/1-Cに進まない）。** 短期平均回帰に未見期間の生エッジなし＝OBS000027/029型として限定的棄却（粒度=1h・エッジ=microstructure mean-reversion・銘柄=BTC/ETH・期間=2022-2026・取引所=Bitgetを明記した限定棄却。戦略クラス全体の一般化棄却はしない＝030/029の教訓）。

### Stage 1-B — スリーブ単体（ネットコスト後Sharpe）＝グロス→ネットの罠検出
G1A通過を前提に、§4のネットコストを引いたスリーブ純リターン列を構築。バー単位で建玉をmark-to-market（保有中は各バーのリターンをposition符号で加算）、エントリー/イグジットのバーで往復コスト（S-taker・銘柄別・$50k）を控除。バー損益を**UTC日次に集約**して日次純リターン列を作る。**BTC・ETH 各々独立に。**
- 出力（銘柄別・確認/R-bear/R-recovery/R-recent）: **ネット年率Sharpe（√365）**・累積ネットリターン・最大DD・年間トレード数・**年間コストドラッグ(bps)**。参考として**グロス年率Sharpe**も併記（グロス陽性/ネット陰性の罠＝OBS000025型・030 Stage1型を可視化）。副モデル(S-maker)・$100k感応度のネットSharpeも併記。
- **G1B（スリーブが壊れていないことの必要条件）**: 確認期間で **BTC・ETH の両方**で**ネット年率Sharpe > 0**（S-taker往復コスト控除後もプラス）。
  - **G1B未達（ネットSharpe ≤ 0）** → グロスで出てもネットで死ぬ＝本テーマ最大の罠に該当し、スリーブとして不採用。
  - G1BはPJ000001 5.4節に従い**単体Sharpeの高さは要求しない**（0.4未満でも可）が、**ネットがプラス（＝コスト後に価値を毀損しない）**ことは必須。**G1B単独では採用しない**（採否の主軸は限界寄与＝Stage 1-C）。

### Stage 1-C — ②との合成（採用の主ゲート＝ポートフォリオ限界寄与・PJ000001 5.4）
G1B通過を前提に、スリーブ日次純リターン（BTC/ETHそれぞれ、および等ウェイト合算スリーブ）と、②単体（日足モメンタム）のリターン列を突き合わせ、限界寄与を測る。
- **②単体の定義**: `simulatePortfolio` を BTC `btc-daily-binance-2017-2026.csv` で本番構成（`horizon:10, k:30, initialEquity:1_000_000, momentumLookback:30, momentumConfidenceScale:30`）で確認期間に回し、`equityCurve` から日次リターン列を得る（029 Stage3と同一）。参考としてETHでも同時算出し併記。
- **合成ウェイト（回す前に固定・HARKing防止）**: **選定期間（2019-08〜2021-12）**の各日次リターン列の標準偏差から**逆ボラ（リスクパリティ）ウェイトを算出し凍結**。確認期間ではこの凍結ウェイトのみ適用（確認データでウェイトを最適化しない）。副次として**素朴50/50**も併記。
- **G3C（低相関＝存在意義・5.4基準1）**: 確認期間で `|corr(スリーブ日次純リターン, ②日次リターン)| < 0.3`（確認全体＋前半/後半別を出力）。
- **G4C（合成の上乗せ・5.4基準2・下記いずれかを満たす）**:
  - (a) **合成Sharpe改善**: 凍結ウェイト合成の確認期間Sharpe − ②単体Sharpe **≥ +0.15**、かつ最大DDが②単体比 **+2pt を超えて悪化しない**。**または**
  - (b) **合成DD削減**: 凍結ウェイト合成の確認期間 最大DD − ②単体 最大DD **≤ −5pt**（5ポイント以上削減）、かつSharpeが②単体比 **−0.05 を下回って悪化しない**。

### 採用 / 不採用（回す前に確定）
- **採用（候補）**: **G1A かつ G1B かつ G3C かつ G4C** を確認期間（2022-2026）で全て満たす（G1A/G1BはBTC・ETH両方）。
  - ※これはCの「採用推薦」であり、本番反映(D起動)は**司令塔の最終GO**を要する（PJ000002鉄則）。
- **不採用**:
  - **G1A未達** → 即打ち切り（予測単位で無エッジ・OBS000027/029型）。
  - **G1B未達（ネットSharpe≤0）** → グロス陽性でもネットで死ぬ（本テーマ最大の罠）で不採用。
  - **G3C未達（|ρ|≥0.3）** → ②と相関が高く「②と直交する低相関アルファ」の前提が崩れる＝分散価値なしで不採用（たとえ単体Sharpeが高くても採らない・5.4基準1）。
  - **G4C未達** → 合成しても改善もDD削減もしない＝上乗せ価値なしで不採用（5.4基準2）。
- 参考: ②単体BTCの現状Sharpe≈0.40〜0.67（設定・期間による）。本スリーブは低相関×DD削減で②を押し上げるかが本質（単体Sharpeの高さではない・5.4）。

### kill基準（チューニング逃避・HARKingの禁止）
事前登録した本spec（エッジ=microstructure mean-reversion 1本、粒度=1h、K=3/W=168/Z_enter=2.0/N=3、非オーバーラップ、等ノーション$50k、S-taker主ゲート、逆ボラ凍結ウェイト、G1A〜G4C）の下で未達なら、**仮説を棄却して不採用で停止**する。確認結果を見てから **粒度・K・W・Z_enter・N・エッジ方向（平均回帰↔順張り）・コスト前提（S-taker↔S-maker・名目サイズ）・合成ウェイト・レジーム窓・permutation seed を調整して再測定してはならない。** 別案は本実験のリスコープではなく別OBSの新規起票でのみ許可する。

## 7. 縮退リスク注記（C品質チームが最初に叩くべき論点）
- **平均回帰は「レンジ・過剰反応が頻発する局面」で機能し、持続トレンド（2022弱気の一方向下落）で轢かれてDD**。よって確認期間全体のネットSharpeが正でも、**R-bear（2022）で大きく負ければ実運用の破産リスク**。Cは R-bear のネットSharpe/DDを必ず個別に確認すること（本specは対応する生データを出力させる）。
- Cが最初に検証すべき点（本specは対応する生データを必ず出力させる）:
  1. **確認期間の前半/後半どちらでもG1Aが立つか**（片側の1局面依存でないか）。
  2. **R-bear/R-recovery/R-recent のどこかにネットPnLが集中していないか**（特定レジーム1発依存の検出）。
  3. **BTCとETHの両方で独立に成立しているか**（片側の偶然でないか＝§5クロス資産要件）。
  4. **グロス陽性/ネット陰性の乖離**（コスト無視の見かけエッジの排除・G1Bで担保。年間コストドラッグを必ず確認）。
  5. **permutationがSharpe不変シャッフルになっていないか**（030で検出したpower0検定の轍。リターン系列そのものの並べ替えか）。
- 上記いずれかで脆弱性が露呈すれば、G1A〜G4Cを数値で満たしても**Cは偽陽性として不採用を宣告してよい**（見かけの数値クリアより頑健性を優先）。
