## 過去の不採用パターン・関連実験との重複チェック ← 本prescreen最重要の切り分け

### OBS000022（Fundingキャリー"方向性"版・不採用）との異同 ＝ 別物、入口で弾く重複ではない
- **OBS000022の敗因**: Fundingを"方向の当てもの"（逆張り/順張りタイミング）に使い、確認ETHで負・非有意（順張り版は②モメンタムの焼き直しで同相）。=**方向予測族**の一員。
- **SYS-001（032）は方向を当てない**: VRPはIV>RVという分散リスクプレミアムの収穫で、価格の上下も金利の符号も当てない。022が死んだ「方向予測として薄い・②と同相」は SYS-001 に一切当てはまらない。生成過程が根本的に異なる。**入口で弾く重複ではない。**

### 8連敗族（027/029/030/031等）との決定的差
- 8連敗は全て**予測単位（グロス/IC段階）で最初から無エッジ**だった。SYS-001は lab側で予測単位が **block-bootstrap p=0** で有意（選定→確認とも有意）＝"回す前にプラス期待値の事前確率がある"点で質的に異なる。Cが壊しにいく主戦場は「無エッジか」ではなく「テール込みで純プラスか／既存スリーブとテール独立か／実コストで崩れないか」へ移る。

### OBS000032（Fundingキャリー）との関係 ＝ 別エッジだが"同族"。ここが本prescreenの独立審査の核心
- **重複ではない（別のエッジ源泉）**: OBS000032のエッジは**Fundingプレミアム**（レバレッジ需要が払う金利）、SYS-001のエッジは**バリアンスプレミアム**（オプション買い手が払う恐怖プレミアム＝IV>RV）。駆動因が別で、入口で弾く重複ではない。むしろ在庫ゼロの低相関スリーブを2本目として供給しうる素材。
- **しかし"ショート・リスクプレミアム"という同族**: 両者とも「平時に小銭を拾い、稀なテールで鋭く損失を出す」プロファイル（蒸気ローラーの前で小銭拾い）を持ち、**危機時（2020-03型）に同時に吹く相関がある**疑いを最初から持つべき。平時の相関ρが低くても、危機時に相関が1へ収束すれば分散効果は目減りする。
- **独立審査としての結論**: これは「入口却下」ではなく「**採否ゲートの設計に織り込むべき条件**」。P3（スリーブ限界寄与）を**平時ρ<0.3だけでなくテール時の同時ドローダウンでも判定する**ことを必須化する（POC計画書 §1-2 P3が既にこれを含むが、prescreenとして改めて格上げ確認する）。OBS000032がフォワード較正中で本番未確定の今、SYS-001を"3本目"として楽観計上（合成Sharpe 1.5射程）するのは早計であり、テール独立性が確認できて初めて分散価値を計上する。

### crypto-strategy-lab（別リポジトリ）のB/C結果を"採用の十分条件"にしない
- lab側のB実装・C検証は**別リポジトリの別エージェント**が行った。trading-app-v2で「採用」を宣告するのは本プロジェクトのC品質チーム。lab結果は**存在検証グレード**（有望性の根拠）として受け入れるが、trading-app-v2側のB実装が予測単位・会計を**独立に書き直してlab結論を再現**できるかを確認する（コピペ流用は030/031型power0バグの輸入リスク）。OBS000032で「Binanceバックテストは存在検証グレード、本番採否はフォワード較正＋Cの独立監査」と切り分けた前例と同じ論理。

## 市場観点の評価

### 想定するエッジの源泉 ＝ バリアンス・リスクプレミアム（非方向性の構造的プレミアム）
- **筋は良い。** VRP（IVが事後RVを構造的に上回る差）は、株式（VIXプレミアム）でも暗号でも**学術・実務で最も確立したリスクプレミアムの一つ**。オプションの買い手（下方保護・投機）が支払う恐怖プレミアムを、売り手（＝本戦略）が構造的に受け取る。価格方向を当てる必要がなく（ICゼロでも成立）、8連敗の"価格→方向"族とは生成過程が根本的に異なる。
- **駆動因の直交性**: VRPはボラの需給（保険需要）に駆動され、②モメンタム（価格方向）・OBS000032キャリー（金利需給）とは駆動因が別。5.4新KPI「ポートフォリオ限界寄与（低相関×合成改善）」に刺さる素材ではある。**ただし前述の"同族テール相関"がこの直交性を平時限定にする疑いがあり、そこが検証の本丸。**

### 市場構造上の妥当性（板・流動性・執行）
- **BTCオプション（Deribit）はデルタニュートラル・ショートボラの主戦場として板・流動性ともに実在**。DVOL指数は2021前半〜連続取得可（lab確認済み）。POC段階はペーパートレード＝公開データのみで執行リスクは負わない。
- **リスクの本質はガンマ/ベガ**: ショートボラはRVがIVを上回る局面（ボラ・スパイク）でガンマ損を鋭く出す。デルタニュートラルは価格方向に中立だが**ボラ方向（ベガ・ガンマ）には裸**。これが「小銭拾い×稀な鋭い損失」の損失側の主機構＝OBS000032のベーシスリスクと構造的に同型。
- **バリアンススワップ近似の限界**: POCはDVOL×RVのバリアンススワップ近似で、実オプション建値ではない。実銘柄での再現はlab Stage 3で無料データの壁に当たり本実装フェーズへ繰り延べ済み（近似と実建値の乖離は本実装課題）。

### レジーム依存性の見立て
- VRPは**低ボラ・平穏レジームで安定的にプラス**、ボラ・レジームシフト（急落・パニック）で鋭い損失。②モメンタムが強トレンドで勝ちレンジで負け、OBS000032キャリーが平穏で勝ち危機で負けるのに対し、**SYS-001も平穏で勝ち危機で負ける＝OBS000032とレジーム勝ち負けがほぼ一致する疑い**。ここが分散価値を毀損しうる核心。合成での分散効果は平時に効き危機時に薄れる非対称性を、テール窓で明示的に測る必要がある。
- **エッジの縮小傾向**: lab側でVRPが選定+15.07→確認+7.79へ半減。FTX窓+3.61はテールでも辛うじてプラスだが薄い。将来さらに縮小しうる点は正直に見る。

### Kelly・破産確率のサニティ ← ここが最も危険（OBS000032と同じ罠）
- **lab側のSharpe 2.94を破産確率のサニティに使ってはならない見かけの数字**。ショートボラは低ボラ・インカム性で日次分散が小さくSharpeが高く出るだけで、損益分布は**正規でなく左に太いテール**（平時ほぼ一定の小益＋稀に大損）。Sharpe（ボラ基準）でKellyを張ると**テールを無視して大幅に過剰レバレッジ**になり、一度のボラ・スパイクで破産し得る典型的な「ピックアップ・ペニー」構造。
- **サイジングはCVaR基準**（lab側で既にCVaR下側5%=−27.997・週次リスク予算=資本2%を採用）＝OBS000032で確立したCVaR駆動サイジング方式を踏襲。**Sharpe基準Kelly禁止・破産確率サニティ必須**。テール被害幅が未実測・未較正のうちは本番サイジングを一切張らない（POCはペーパーのみ）。

## データ実現可能性の厳格評価（030/031/032の教訓を最優先で適用）

**結論: 本テーマの検証も"データ調達＋実コスト実測"が最大の関門。以下をStage 0で先に潰す。**
1. **Deribit公開APIの米国IPアクセス可否**: GitHub Actions（米国IP）から DVOL・価格エンドポイントにアクセスできるか。OBS000032でBinanceが451地理ブロックを返しF2ゲートが恒常null化した前例と同種のリスク。未確認事項としてStage 0の単独ゲートで潰す（不可ならプロキシ等インフラ対応の要否を司令塔に上申）。
2. **テール到達性（DVOL 2021起点の制約）**: DVOLは2021前半〜。**2020-03コロナ級テールが構造的に測定不能**。LUNA窓（2022-05）・FTX窓（2022-11）はカバー可（lab: LUNA+10.44/FTX+3.61）。ゆえに「最大級テールはバックテストで観測できない＝フォワード較正でテール込み挙動を積む」という設計が必須（OBS000032と同型）。フォワード単独はテールを"来るまで観測できない"が、少なくとも改竄不能な前向き蓄積で実現VRPと会計を検証する。

## GO/却下の理由（回す前に言えるリスク・期待値・優先度）

**段階的・条件付きGO。** 理由:
1. **却下にしない理由**: (a)8連敗の"方向予測族"の外にある非方向性のリスクプレミアム収穫で、予測単位が最初の関門で死ぬ族と質的に異なる。(b)lab側で予測単位（p=0）×会計（Sharpe 2.94・コストx2頑健）まで通過済み＝回す前にプラス期待値の事前確率がある。(c)OBS000022（方向性版）とは別物、8連敗とも別族、OBS000032とは別エッジ。頭ごなしの拒否は機会損失。②の職務改訂（アルファ生成＆配分層）が要求する低相関スリーブ在庫の2本目候補。
2. **無条件GOにもしない理由**: 生死＝テール被害幅がDVOL 2021起点で最大級テールを観測できず、かつ**OBS000032と同族ゆえテール時に同時に吹く疑い**があり、かつコスト前提が仮置き。この3点を先に潰さないと、平時の綺麗な右肩上がり曲線に釣られた偽陽性に直結する。ゆえにStage 0単独ゲート化＋テール相関の第一級ゲート化を必須とする。
3. **優先度（OBS000032がフォワード較正中である点を踏まえた判断）**: **中〜高。並行着手可だが"本命の2本目"として過度に前のめりにしない。**
   - **並行着手が可能な理由**: OBS000032のフォワード較正はF2母集団インフラ確認済みで、以降は主に**時間経過でday90（予定2026-10-02）に到達するのを待つ受動フェーズ**。日次実行は自動化されており重い計算リソースを占有しない。SYS-001のStage 0（Deribitデータ実現可能性＋米国IP＋実コスト実測手段）は**安価で独立**に走らせられ、パイプラインのアイドル時間を有効活用できる。
   - **前のめりにしない理由**: SYS-001とOBS000032は同族（ショートリスクプレミアム）。OBS000032がまだ本番反映未確定（フォワード合格＋C正式監査＋司令塔GOの3点未達）の段階で、同族の2本目を"合成Sharpe 1.5射程"と楽観計上して本実装リソース（Deribit執行アダプタ＝全く別基盤）まで踏み込むのは、**相関した2つの賭けを本番に同時投入するリスク**を孕む。**SYS-001は Stage 0（データ・コスト feasibility）までを先行させ、シグナル最適化・本実装の本格投資は「テール独立性の見込み」＋「OBS000032フォワード較正の中間結果」を見てから段階的に判断する**のが健全。
   - **したがって**: A設計官へは **Stage 0 spec化のGO** を出す（Deribitデータ実現可能性・米国IPアクセス・実コスト実測手段・OBS000032とのテール相関測定設計を含む）。Stage 1（予測単位再現・会計・フォワード）への進行、および本実装フェーズへの投資判断は、Stage 0通過後に改めて司令塔判断とする。

## 段階分けとゲート（A設計官への必須の引き渡し）

### 必須条件（2点・prescreenとしての格上げ）
- **必須条件A（テール相関の第一級ゲート化）**: P3（スリーブ限界寄与）を平時|ρ|<0.3だけでなく、**テール窓（LUNA/FTX、およびフォワードで観測される任意のボラ・スパイク）での②主軸＋OBS000032キャリーとの同時ドローダウン**で判定すること。平時ρが低くても危機時に相関1へ収束するなら分散価値を計上しない。これを spec で数値固定（HARKing防止）。
- **必須条件B（lab結果の独立再現・存在検証グレード扱い）**: lab側のStage 1（予測単位）・Stage 2（会計）は"存在検証グレード"として受け入れる（ゼロから全数探索やり直しは多重検定・リソース浪費で不適）。ただしtrading-app-v2側のB実装が `vrp-prediction-unit.ts`／`vrp-pipeline-accounting.ts` を**独立に書き直してlab結論（BTC平均VRP・p値・Sharpe・maxDD）を再現**すること（コピペ流用禁止＝labのバグごと輸入するリスク回避）。新規パラメータ探索は禁止（labで確認済みの結論の"再現"に徹する）。

### Stage 0 — データ実現可能性＋実コスト実測（go/no-go・シグナル検証の前提条件）
Stage 0の合否ゲート（A設計官が回す前に数値で固定・案）:
- **G0-1（Deribit米国IPアクセス性＝最優先の単独ゲート）**: GitHub Actions実行環境からDVOL指数・価格エンドポイントを取得できるか。不可なら（OBS000032のBinance 451と同型）プロキシ等インフラ対応の要否を司令塔上申。データ土俵が立たなければシグナル検証に進めない。
- **G0-2（DVOL履歴深度・RV自前計算の実現可能性）**: DVOL 2021起点でLUNA/FTX窓をカバーできるか、価格からRVを整合的に計算できるか。2020-03級テールが窓外である旨を明記（フォワードで積む前提）。
- **G0-3（実コスト実測手段）**: Deribitの実手数料・スプレッド・デルタヘッジ滑りを実測に置換する手段を構築できるか。lab仮置き（往復1.5＋ヘッジ0.3 vol pt/週）を実測へ置換後もネットプラス・Sharpe優位（年率Sharpe≥1.0、コストx2でも正）を保つか。
- **G0-4（フォワード較正ハーネスの実現可能性）**: OBS000032の `bitget-carry-forward-paper.ts` を雛形に `deribit-vrp-forward-paper.ts`（仮称）を新設し、日次冪等追記型ledgerで前向き蓄積できるか（warmup back-fill＋go-live確定＋ライブ≥90暦日、back-fillで90日を一括生成しない＝ライブ性厳守）。

成立しない場合の分岐: OBS000030/032同様、Sと司令塔に上申（G0-1未達＝インフラ投資判断、G0-3で実コスト後にネット負転＝土台崩壊で保留）。

### Stage 1以降 — 予測単位再現・会計・フォワード較正（Stage 0通過後のみ）
- 予測単位（VRP検定・block-bootstrap）と会計（CVaRサイジング）をlab独立再現→実コスト置換後会計→OBS000032方式のF1〜F4相当をA設計が数値固定→ライブ≥90暦日フォワード較正→C正式監査→司令塔最終GO。

## 補足（司令塔・A設計官向けメモ）
- 本prescreenの成立可否は最終的にStage 0の実測（Deribit米国IPアクセス・DVOL深度・実コスト後ネット期待値）に依存する条件付きGO。G0-1未達ならインフラ投資判断で司令塔上申に戻し得る。
- **本テーマがこれまでと質的に違う点**: 8連敗は「エッジがあるか（予測単位）」で死んだ。SYS-001はlab側で「エッジは(平時)あり＝p=0」を出発点に、「テール込みでも純プラスか」「OBS000032とテール独立か」「実コストで崩れないか」で真贋を問う。Cが壊しにいく主戦場が"無エッジ"から"テール/同族相関/コスト前提/偽陽性(平時の綺麗な曲線)"へ移る。
- **Sの正直な事前確率**: 平時VRPの存在≈高（lab p=0＋VRPは確立プレミアム）、テール込み純プラスの持続≈中（コスト実測・ボラスパイク被害幅次第）、②＋032合成での限界寄与（真の分散価値）≈**中〜やや低め**（032と同族ゆえテール相関で目減りする疑いが本命リスク）。**楽観の理由にはせず、テール独立性とデータ/コスト feasibility を最初のゲートで確かめる姿勢で臨む。**
