## 現在の技術的ボトルネック

### 1. **Phase 1 の頑健性課題**
**課題**: 単一期間での過最適化
- 単一分割: 2021-2026年全期間で 57.7%（k=30, horizon=10）
- 複数期間フォールド: 直近期間で50%以下へ低下
- 原因: 特徴量設計（高値幅・低値幅・体積）が直近の相場環境に依存しすぎている可能性

**現在の改善アプローチ**:
- `src/pattern-engine/features.ts` で試行された Efficiency Ratio によるレジーム条件付けは有意な改善なし
- 次のステップ: (a) 特徴量の微調整、(b) モデルのアンサンブル化、(c) Phase 3の④統合ルール調整のいずれかが必要だが、プロジェクト方針では Phase 2 ③の実検証を優先

### 2. **③LLM層の実LLM化が完全には未検証**
**課題**: mockでは配線確認できたが、実LLM呼び出しの効果は未測定
- mock（キーワードマッチ）ではシャープレシオ -0.82と悪化 → 粗い感情判定はveto誤発動の原因に
- **実LLM（Claude Haiku）の解釈力次第で大きく変わる可能性がある**

**ユーザ作業として残存** (OBS000014):
```bash
set ANTHROPIC_API_KEY=sk-ant-...
node --experimental-strip-types scripts/llm-feature-extraction.ts --limit 5   # 小規模テスト
node --experimental-strip-types scripts/llm-feature-extraction.ts             # 全期間実行（推定$4）
node --experimental-strip-types scripts/pipeline-backtest-llm.ts              # ③あり/なし比較
```

### 3. **Phase 3のシャープレシオが目標未達（0.44 vs 目標0.8）**
**課題**: 直近期間の収益性が低下
- ④統合判断層は「②が確信度≥50%」「③が否定的でない」のveto方式
- ⑤リスク管理は Kelly比率（フラクション=0.25）で保守的に設計
- しかし現状では過度に慎重すぎるか、特徴量の質が問題か、判定ロジックが不適切か、まだ不明確

**改善の候補**:
- (a) ③の実検証で感度が上がれば改善の余地あり
- (b) ④の統合ロジックを学習ベースに変更（決定木・ロジスティック回帰等）
- (c) ⑤のKelly係数やサーキットブレーカー閾値の最適化

## 現在のリスク・懸念点

### 1. Phase 1の品質が低い状態で進行している
- 方向的中率が直近期間で50%以下では、統計的な優位性がない
- 結果的に④⑤のリスク管理がいかに堅牢でも、ベースの判定ロジックが信頼できないと本番運用は危険

### 2. ③の効果が未検証のまま次へ進む可能性
- ユーザのAPIキー設定がまだなので、実LLMでの効果がわかっていない
- mock（キーワード）ではむしろ悪化しているため、期待値管理が必要

### 3. シャープレシオ目標の達成見通しが立っていない
- 目標0.8に対して現状0.44。倍近い改善が必要
- Phase 2の③効果如何では少しは改善するかもしれないが、それだけでは足りない可能性が高い

### 4. リアルタイムデータ調達の課題
- 本環境からのAPI呼び出し（Binance等）がブロック済
- 現在はGitHub経由のCSVデータで検証しているが、本番運用時のデータパイプラインが未構築
