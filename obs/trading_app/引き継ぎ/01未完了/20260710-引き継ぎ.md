#### 2026-07-11 発見・修正: Bitget v2移行漏れ4件（コミット `c64bdf0`, `56aa913`）
Secrets登録後の初回workflow_dispatchでDiscordにエラー通知が来たことから発覚。Bitget公開APIへの直接検証で全て確認済み。
1. `config/strategy-params.json` の `symbol_perp` が v1形式 `"BTCUSDT_UMCBL"` のまま → `"BTCUSDT"`（v2形式）に修正
2. `bitget-client.ts` の `Ticker.last` → 実際のv2レスポンスは `lastPr` フィールド（`execute-daily.ts`/`open-position.ts`の価格取得が常にNaNになる状態だった）
3. `getPositions()` のURLが `/api/v2/mix/position/allPosition` → 正しくは `/api/v2/mix/position/all-position`（404で証拠金監視が機能しない状態）
4. `placeSpotOrder`/`placePerpOrder` のURLが `.../placeOrder` → 正しくは `.../place-order`（404で**実注文が完全に失敗する状態**だった）

ドライランでは注文発行・ポジション確認系が呼ばれないため気づかれず、LIVE_MODE=true切替時に初めて露見するところだった。修正後、workflow_dispatchで`signal_computed`まで正常完了を確認済み。

#### 2026-07-11 続報: Bitget公式v2ドキュメント照合で追加4件を修正（コミット `7e3958d`）
上記`side`パラメータの残課題に対応するため、Bitget公式v2ドキュメントをWebFetch/WebSearchで直接参照して照合。以下4件の不整合を確認・修正。
1. `placePerpOrder()`: `side`に`"open_short"`等の複合文字列（v1形式）を直接送信していた → v2は`side=buy/sell`のみ有効、open/closeは別の`tradeSide`パラメータ（hedge-mode時必須）で指定する仕様。公式マッピング表通りに分離済み
2. `placeSpotOrder()`: 市場成行買いで`quoteSize`という独自パラメータを送信していたが**v2にこのフィールドは存在しない**（公式パラメータ表で確認）。`size`フィールドにUSDT建て金額を直接入れる仕様。**現物ロング注文（ポジションオープンの1本目）が必須パラメータ欠落で失敗する状態だった**
3. `getPerpAccount()`: `/api/v2/mix/account/account`（Get Single Account）を`symbol`なしで呼んでいたが、公式ドキュメントでは`symbol`必須。用途に合わないため`symbol`不要な`/api/v2/mix/account/accounts`（Get Account List）に切替
4. `getFundingRate()`: `/api/v2/mix/market/funding-rate`が404 → 正しくは`/api/v2/mix/market/current-fund-rate`（現状未使用関数だが修正済み）

いずれも公開APIへの直接curl検証＋公式ドキュメントで確認済み。ドライランでworkflow_dispatch実行し`signal_computed`まで正常完了を再確認。

## 解決済みの既知問題

### F2 Binance 地理ブロック（451エラー）— 2026-07-11 解消
- **症状**: `eventSignAgreementPct = null`、F2判定が出ない
- **原因**: GitHub Actions（米国IP）から `fapi.binance.com` への直接アクセスが451地理ブロックされる（ローカル日本からは200で到達可能と確認済み）
- **対応**: Firebase Blazeプランへ切替（課金設定・予算アラート¥1,000/月を設定済み）。asia-northeast1にCloud Functions(2nd gen)の中継プロキシ `functions/binanceFundingProxy` を新設し共有トークンで保護。`scripts/bitget-carry-forward-paper.ts` を `BINANCE_PROXY_URL`/`BINANCE_PROXY_TOKEN`（GitHub Secretsに設定済み）経由でBinance funding rateを取得するよう修正（未設定時は従来通り直接アクセス＝ローカル実行は無変更）。
- **確認結果**: GitHub Actions実運用環境でBTC/ETHとも22件のfunding取得に成功、F2イベントペア一致率81.8%（閾値80%達成・試験値）を記録。コミット `7b22f99`。
- **運用コスト**: Cloud Functions呼び出しは1日数回・数KB程度のため無料枠内（実質0円運用）。
