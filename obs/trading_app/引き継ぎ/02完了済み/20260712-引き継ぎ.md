## 今回新規実装：`/carry-executor` 実行状況モニター画面

btc-carry-executorのドライラン稼働状況を、trading-app-v2のWebアプリ（スマホ対応・Google認証済み）から常時確認できるようにした。

### アーキテクチャ
```
[btc-carry-executor repo（プライベート）]        [trading-app-v2 repo]
execute-daily.ts (毎日00:05 UTC)
  → status/latest-signal.json 書き出し・commit・push
                                                  carry-executor-sync.yml（4時間毎）
monitor-margin.ts (毎4h)                            → PATでbtc-carry-executorの
  → status/latest-margin.json 書き出し・commit・push   status/*.json＋直近実行履歴を取得
                                                     → public/data/carry-executor/status.json
                                                       へ統合してcommit・push
                                                  → deploy.ymlが自動発火しFirebase Hostingへ反映
                                                  → /carry-executor 画面に表示
```

### 実装ファイル
- **btc-carry-executor**: `scripts/execute-daily.ts`・`scripts/monitor-margin.ts`（`writeStatus()`追加）、`.github/workflows/daily-run.yml`・`monitor-margin.yml`（`status/`のcommit・pushステップ追加）
- **trading-app-v2**: `.github/workflows/carry-executor-sync.yml`（新規）、`src/hooks/useCarryExecutorData.ts`（新規）、`src/components/screens/CarryExecutorScreen.tsx`（新規）、`src/App.tsx`（ルート追加）、`src/components/shell/navItems.ts`（「実行状況」エントリ追加）

### ハマったポイント（次回同種の作業をする際の参考）
1. **`git diff --quiet`は未追跡（untracked）ファイルの新規作成を検知しない**。`status/`や`public/data/carry-executor/`がリポジトリに一度も存在しない初回実行では「変更なし」と誤判定されコミットがスキップされる。`git status --porcelain`に置き換える必要がある。
2. **同一ディレクトリへの複数workflowからの同時コミットはpush競合を起こす**（daily-run.ymlとmonitor-margin.ymlがほぼ同時刻に実行された場合）。`git pull --rebase`＋リトライ（３回）で対応。リトライ全滅時に無言で「成功」扱いにならないよう、明示的な成否判定と`exit 1`が必要。
3. **Fine-grained PAT（プライベートリポジトリのクロスリポジトリ読み取り用）の設定で、何度再発行しても`gh api user`単体でも401 Bad credentialsになる事象が発生**（原因は最後まで特定できず）。**Classic PAT（`repo`スコープ）に切り替えたら即座に解決**。次回同様のクロスリポジトリ連携が必要な場面では、最初からClassic PATを使う方が無難かもしれない。
4. C品質チームによるレビューは今回、トレード戦略ではなくインフラ・観測系のコード変更にも適用した（司令塔の明示的な依頼を受けて）。実装中の自己発見バグと合わせ、計9件の潜在バグ（未追跡ファイル検知漏れ・push競合・証拠金ゼロ中断時のstatus書き出し漏れ・margin取得失敗時の書き出し漏れ・アラート例外での書き出しスキップ・pushリトライ全滅の無言成功、②〜⑨関連の資金リスクバグは含まず）を発見・是正できた。

### 画面の表示内容
- ワークフロー稼働状況（Daily Signal Check / Margin Monitorの直近実行を成功/失敗ドットで表示）
- シグナル状況（BTC/ETHそれぞれのカードでオープン/クローズ/保留・SMA値・ポジション有無）
- 証拠金状況（ポジション一覧。BTCUSDT/ETHUSDT以外は「戦略対象外」の注記付き — 現在`SPCXUSDT`という戦略と無関係なロングポジションが同一Bitgetアカウント上に存在することが判明しており、画面上でも表示される。想定内かどうかは司令塔未確認のまま）
- 中断（`aborted`）・証拠金critical/warn・fetchError発生時のアラートバナー
