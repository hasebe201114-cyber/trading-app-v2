## 1. コンセプト

現在の相場状況と過去の相場の類似パターンを抽出し、この先の価格の**方向・強さ・確度**を予測して、エントリータイミング・決済タイミング・エントリー数量を決定し自動売買するトレードエンジンを構築する。

統計的パターン認識だけでは持続的な優位性を得にくいという認識のもと、LLM（生成AI）が持つ「定性情報の解釈力」を**プラスエッセンス**として組み込む。ただし、LLMにトレード可否そのものを判断させるのではなく、検証可能な数値ロジックの入力（特徴量・フラグ）に変換する役割に限定し、システム全体の再現性・検証性を確保する。

## 2. 全体アーキテクチャ（7層構成）

```
① データ層
    ↓
② パターン認識・統計シグナル層（コア予測エンジン）
    ↓                    ↑
③ LLM特徴量抽出層（プラスエッセンス）
    ↓
④ 統合判断層（方向・強さ・確度）
    ↓
⑤ リスク管理・ポジションサイジング層
    ↓
⑥ 執行層（エントリー/決済）
    ↓
⑦ 評価・チューニング層（層横断で常時稼働）
```

## 3. 各層の詳細

### ① データ層
- 価格・出来高（複数時間足: 1m/5m/15m/1h/4h/1d）
- オンチェーンデータ、オーダーブック・Funding Rate・OI（既存 btc-strategy の API 資産を流用）
- ニュース・センチメント、マクロ相関（DXY・株式指数・金利等）

### ② パターン認識・統計シグナル層（コア予測エンジン）
- 直近N本の価格変化率・ボラティリティ・出来高変化・テクニカル指標をベクトル化
- k近傍探索やDTW等で過去の類似局面を抽出
- 近傍サンプルの将来リターン分布から **方向 / 強さ / 確度（ばらつきの小ささ）** を算出

> **2026-07-04更新**: 上記k-NN方式はBTC単独では動いたが、ETHクロス検証（OBS000019）で全く再現せずBTC固有の過学習と判明。後継としてトレンドフォロー(モメンタム, 直近30日リターンの符号)を検証したところ、パイプライン統合バックテストの9通りの比較のうち8つでk-NNを上回った（OBS000020, OBS000023）。**現在はモメンタムベースの実装（`simulatePortfolio`の`momentumLookback`オプション）を②の主軸として採用**し、k-NN実装(`pattern-engine/`)は比較・研究用に残している。上記のk-NN/DTW記述は初期仮説として保持するが、実装の主軸はモメンタムに移行済み。
- 決定的でバックテスト可能であることを最優先（パラメータはバージョン管理）
- 過学習防止のため walk-forward 検証を必須とする

### ③ LLM特徴量抽出層（プラスエッセンス）
- ニュース速報・要人発言のインパクト評価（スコア化・影響持続期間の推定）
- オンチェーン異常のナラティブ解釈
- 市場レジーム分類（トレンド/レンジ/ボラティリティ急拡大）→ ②の類似局面探索の絞り込みに使用
- 出力は数値・カテゴリのフラグに限定し、そのままトレード可否を判断させない
- 判断根拠は全てログ化し、事後に妥当性検証できるようにする（トレーサビリティ確保）

### ④ 統合判断層
- ②の(方向・強さ・確度)と③のフラグ・レジーム判定を組み合わせて最終シグナルを生成
- 初期はルールベース（例：③が重大ネガティブイベントを検知したら②のシグナルを縮小/見送りにするveto方式）
- 将来的には統合ロジック自体もバックテストで検証・チューニング対象とする

### ⑤ リスク管理・ポジションサイジング層
- 確度に応じた動的サイジング（フラクショナルKelly推奨、フルKellyは禁止）
- 最大ポジション上限、1トレード最大損失額、日次/週次ドローダウン上限による自動停止（サーキットブレーカー）
- ②③両方が「確度低」の場合はエントリー見送りをデフォルトとする

### ⑥ 執行層
- エントリー/決済のタイミングは既存の指値/成行ロジックを流用
- スリッページ・手数料を考慮した執行コストモデルをバックテストに組み込む

### ⑦ 評価・チューニング層
下記4章に詳細を記載。

## 4. 評価・チューニング層の詳細

**目的**: 各層の貢献度・性能をバックテスト/フォワードテストで数値化し、目標値との差分からチューニングポイントを継続的に可視化する。一度きりの分析ではなく開発サイクルに組み込む。

### 4.1 層別KPI

| 層 | 評価指標 |
|---|---|
| ②パターン認識層 | 方向的中率、確度帯別の的中率、単体シャープレシオ |
| ③LLM特徴量層 | イベント検知の的中率、③あり/なしのバックテスト成績差分（増分寄与度） |
| ④統合判断層 | 統合後 vs ②単体の成績差分 |
| ⑤リスク管理層 | 最大ドローダウン抑制効果、実現ボラティリティ vs 目標ボラティリティ |

### 4.2 目標値管理
各指標に目標値（5章参照）を設定し、実績と継続比較する。

### 4.3 貢献度の数値化
Ablation方式（各層をON/OFFしてバックテスト成績差分を測る）で寄与度を算出。パラメータの感度分析も記録する。

### 4.4 チューニングポイントの自動抽出
目標未達の層・指標を自動フラグ化し、レポート化する（例:「③LLM層のイベント検知的中率が目標未達→プロンプト/閾値見直し」）。未達項目は自動的に「02対応検討中」の起票候補とする。

### 4.5 機能実装として組み込む内容（開発タスク）
- バックテスト/フォワードテスト実行時に層別成績を自動集計・保存するデータモデル（`backtestReports`/`forwardReports` を拡張し `layerContribution` フィールドを追加）
- 管理画面に「層別評価ダッシュボード」（目標vs実績、時系列推移、チューニング提案一覧）を追加
- 週次など定期実行で評価レポートを自動生成し、未達項目をOBS開発件名として自動起票する仕組み

※ この評価機能自体の実装は、②〜⑥の各層が最低限動く状態になってから着手する（評価対象がなければ評価できないため）。

## 5. ゴール設定

### 5.1 North Star（最終ゴール）
実運用でシャープレシオ **1.5以上**、最大ドローダウン **20%以内** を維持しながら、年率ベースで安定したプラスリターンを継続できる自動売買システムを完成させる。

### 5.2 フェーズ別ゴール

| フェーズ | 内容 | 目標（KPI） |
|---|---|---|
| Phase 1: PoC | ②パターン認識層単体の検証 | walk-forward検証で方向的中率 **55%以上**（ランダム50%を有意に上回る）、単体シャープレシオ **0.8以上** |
| Phase 2: LLM層追加検証 | ③を加えた増分効果の検証 | ②単体比でシャープレシオ **+0.2以上** の改善、または最大ドローダウン **-3pt以上** の改善のいずれかを達成。未達なら③の設計を見直す |
| Phase 3: 統合・リスク管理構築 | ④⑤層の構築 | バックテストで最大ドローダウン **15%以内**、期待値ベースでの月次プラス率 **50%以上** |
| Phase 4: フォワードテスト | 紙トレードでの実データ検証 | 最低 **8週間** の紙トレードで、バックテスト予測との乖離 **±20%以内**（過学習チェック）、シャープレシオ **1.0以上** を維持 |
| Phase 5: 実資金段階導入 | 総資産の **5%以下** からスタート | 3ヶ月間の実績がフォワードテスト目標を下回らなければ段階的に資金を拡大。実資金ベースの最大許容ドローダウン **15%** に達したら自動停止し、本方針を見直す |

### 5.3 評価層の継続KPI（4.1の目標値）
- ②パターン認識層: 方向的中率 **55%以上**
- ③LLM特徴量層: イベント検知的中率 **60%以上**、③あり/なしでシャープレシオ **+0.2以上** の増分効果
- ④統合判断層: 統合後の成績が②単体を **常に上回ること**（下回れば統合ロジックを見直す）
- ⑤リスク管理層: 最大ドローダウン **15%以内**、実現ボラティリティが目標レンジ内

上記の数値は初期仮説値であり、Phase 1のPoC結果を踏まえて妥当性を検証・調整する（変更時は本ドキュメントの変更履歴に記録すること）。
