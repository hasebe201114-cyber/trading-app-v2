## 1. コンセプト

現在の相場状況と過去の相場の類似パターンを抽出し、この先の価格の**方向・強さ・確度**を予測して、エントリータイミング・決済タイミング・エントリー数量を決定し自動売買するトレードエンジンを構築する。

統計的パターン認識だけでは持続的な優位性を得にくいという認識のもと、LLM（生成AI）が持つ「定性情報の解釈力」を**プラスエッセンス**として組み込む。ただし、LLMにトレード可否そのものを判断させるのではなく、検証可能な数値ロジックの入力（特徴量・フラグ）に変換する役割に限定し、システム全体の再現性・検証性を確保する。

## 2. 全体アーキテクチャ（7層構成）

```
① データ層
    ↓
② パターン認識・統計シグナル層（コア・アルファ生成＆配分層）※2026-07-05職務定義改訂・旧名称「コア予測エンジン」
    ↓                    ↑
③ LLM特徴量抽出層（プラスエッセンス）
    ↓
④ 統合判断層（方向・強さ・確度）
    ↓
⑤ リスク管理・ポジションサイジング層
    ↓
⑥ 執行層（エントリー/決済）
    ↓
⑦ 評価・チューニング層（層横断で常時稼働）
```

## 3. 各層の詳細

### ① データ層
- 価格・出来高（複数時間足: 1m/5m/15m/1h/4h/1d）
- オンチェーンデータ、オーダーブック・Funding Rate・OI（既存 btc-strategy の API 資産を流用）
- ニュース・センチメント、マクロ相関（DXY・株式指数・金利等）

### ② パターン認識・統計シグナル層（コア・アルファ生成＆配分層）

> **2026-07-05 職務定義の改訂（根幹）**: 外部アドバイザーレビュー（[20260705-外部テクニカルアドバイザー評価-②コア予測エンジンのゼロベース再設計](../85レビュー/20260705-外部テクニカルアドバイザー評価-②コア予測エンジンのゼロベース再設計.md)）を受け、②の職務定義を「**コア予測エンジン**（現在と過去の類似パターンから方向・強さ・確度を**予測**する）」から「**コア・アルファ生成＆配分層**（**複数の直交するエッジ＝スリーブを生成し、配分する**）」へ改める。
>
> 根拠: OBS000018/022/025/027/028/029/030/031の8連敗はすべて「価格由来の特徴量から将来の方向を予測する」というエッジ族の変奏であり、ブレッド（銘柄数=030・頻度=031）を実際に増やした2実験ではICがゼロ〜負に崩れた。これは「ブレッド不足」でなく、この**エッジ族そのものが効率化の床に達している**ことを示す。②を「より良い方向予測器」に改良し続ける設計思想そのものが、8連敗の構造的な原因だったと判断する。
>
> **改訂の要点**:
> 1. ②の職務は単一の予測器を磨くことではなく、**複数の直交するエッジ（スリーブ）を生成・配分すること**に変わる。方向モメンタムはその1本に過ぎず、"唯一・最良"である必要はない。
> 2. **モメンタム（L=30・確信度scale=30）の生シグナル天井Sharpe（未見基準0.40）は、「日足・順張り・単一資産」という生成過程の構造的な上限として受容する。単体を0.8まで引き上げる努力は停止する**（8連敗が費やしてきた消耗ポイント）。モメンタムスリーブ自体は安価で本物の"トレンド"収益源として②に残す（置換でなく加算・アーキテクチャ変更）。
> 3. 今後の実験投資（革新予算）は、(a) 予測を要さない非方向性のエッジ（例: デルタニュートラル・キャリー収穫）、(b) 非価格フロー由来のコンディショニング、(c) それらを束ねるリスク配分層、へ振り向ける。5.4節「限界寄与」KPIは既に改訂済みだが、判定対象となる**低相関スリーブの在庫が現状ゼロ**（②モメンタム1本のみ）であり、まずこの在庫を作ることが次の実験の主眼となる。
> 4. 具体的な再設計案（複数のベース案）は、開発アイデアとして個別に起票する（`01開発アイデア`、本レビューの§4参照）。

- 直近N本の価格変化率・ボラティリティ・出来高変化・テクニカル指標をベクトル化
- k近傍探索やDTW等で過去の類似局面を抽出
- 近傍サンプルの将来リターン分布から **方向 / 強さ / 確度（ばらつきの小ささ）** を算出

> **2026-07-04更新**: 上記k-NN方式はBTC単独では動いたが、ETHクロス検証（OBS000019）で全く再現せずBTC固有の過学習と判明。後継としてトレンドフォロー(モメンタム, 直近30日リターンの符号)を検証したところ、パイプライン統合バックテストの9通りの比較のうち8つでk-NNを上回った（OBS000020, OBS000023）。**現在はモメンタムベースの実装（`simulatePortfolio`の`momentumLookback`オプション）を②の主軸（トレンド・スリーブ）として採用**し、k-NN実装(`pattern-engine/`)は比較・研究用に残している。上記のk-NN/DTW記述は初期仮説として保持するが、実装の主軸はモメンタムに移行済み。2026-07-05の職務定義改訂により、このモメンタムは②内の唯一のスリーブでなく、複数スリーブのうちの1本という位置づけになる。
- 決定的でバックテスト可能であることを最優先（パラメータはバージョン管理）
- 過学習防止のため walk-forward 検証を必須とする

### ③ LLM特徴量抽出層（プラスエッセンス）
- ニュース速報・要人発言のインパクト評価（スコア化・影響持続期間の推定）
- オンチェーン異常のナラティブ解釈
- 市場レジーム分類（トレンド/レンジ/ボラティリティ急拡大）→ ②の類似局面探索の絞り込みに使用
- 出力は数値・カテゴリのフラグに限定し、そのままトレード可否を判断させない
- 判断根拠は全てログ化し、事後に妥当性検証できるようにする（トレーサビリティ確保）

### ④ 統合判断層
- ②の(方向・強さ・確度)と③のフラグ・レジーム判定を組み合わせて最終シグナルを生成
- 初期はルールベース（例：③が重大ネガティブイベントを検知したら②のシグナルを縮小/見送りにするveto方式）
- 将来的には統合ロジック自体もバックテストで検証・チューニング対象とする

### ⑤ リスク管理・ポジションサイジング層
- 確度に応じた動的サイジング（フラクショナルKelly推奨、フルKellyは禁止）
- 最大ポジション上限、1トレード最大損失額、日次/週次ドローダウン上限による自動停止（サーキットブレーカー）
- ②③両方が「確度低」の場合はエントリー見送りをデフォルトとする

### ⑥ 執行層
- エントリー/決済のタイミングは既存の指値/成行ロジックを流用
- スリッページ・手数料を考慮した執行コストモデルをバックテストに組み込む

### ⑦ 評価・チューニング層
下記4章に詳細を記載。

## 4. 評価・チューニング層の詳細

**目的**: 各層の貢献度・性能をバックテスト/フォワードテストで数値化し、目標値との差分からチューニングポイントを継続的に可視化する。一度きりの分析ではなく開発サイクルに組み込む。

### 4.1 層別KPI

| 層 | 評価指標 |
|---|---|
| ②パターン認識層 | 方向的中率、確度帯別の的中率、単体シャープレシオ（参考値）、**ポートフォリオへの限界寄与**（既存スリーブとの相関の低さ・合成時のSharpe改善orDD削減への寄与）※2026-07-05改訂 |
| ③LLM特徴量層 | イベント検知の的中率、③あり/なしのバックテスト成績差分（増分寄与度） |
| ④統合判断層 | 統合後 vs ②単体の成績差分 |
| ⑤リスク管理層 | 最大ドローダウン抑制効果、実現ボラティリティ vs 目標ボラティリティ |

### 4.2 目標値管理
各指標に目標値（5章参照）を設定し、実績と継続比較する。

### 4.3 貢献度の数値化
Ablation方式（各層をON/OFFしてバックテスト成績差分を測る）で寄与度を算出。パラメータの感度分析も記録する。

### 4.4 チューニングポイントの自動抽出
目標未達の層・指標を自動フラグ化し、レポート化する（例:「③LLM層のイベント検知的中率が目標未達→プロンプト/閾値見直し」）。未達項目は自動的に「02対応検討中」の起票候補とする。

### 4.5 機能実装として組み込む内容（開発タスク）
- バックテスト/フォワードテスト実行時に層別成績を自動集計・保存するデータモデル（`backtestReports`/`forwardReports` を拡張し `layerContribution` フィールドを追加）
- 管理画面に「層別評価ダッシュボード」（目標vs実績、時系列推移、チューニング提案一覧）を追加
- 週次など定期実行で評価レポートを自動生成し、未達項目をOBS開発件名として自動起票する仕組み

※ この評価機能自体の実装は、②〜⑥の各層が最低限動く状態になってから着手する（評価対象がなければ評価できないため）。

## 5. ゴール設定

### 5.1 North Star（最終ゴール）
実運用でシャープレシオ **1.5以上**、最大ドローダウン **20%以内** を維持しながら、年率ベースで安定したプラスリターンを継続できる自動売買システムを完成させる。

### 5.2 フェーズ別ゴール

| フェーズ | 内容 | 目標（KPI） |
|---|---|---|
| Phase 1: PoC | ②パターン認識層単体の検証 | walk-forward検証で方向的中率 **55%以上**（ランダム50%を有意に上回る）。単体シャープレシオ**0.8以上**は参考値に降格し、**主要な採否基準はポートフォリオへの限界寄与**（既存スリーブとの相関 \|ρ\|<0.3程度、かつ合成時にSharpe改善またはDD削減に寄与すること）に置く（2026-07-05改訂、下記5.4参照）。**モメンタム・スリーブ単体を0.8まで引き上げる努力は2026-07-05付けで停止**し（8連敗の消耗ポイント・下記§3の職務定義改訂参照）、実験投資は新規の低相関スリーブ創出（§3参照）へ振り向ける |
| Phase 2: LLM層追加検証 | ③を加えた増分効果の検証 | ②単体比でシャープレシオ **+0.2以上** の改善、または最大ドローダウン **-3pt以上** の改善のいずれかを達成。未達なら③の設計を見直す |
| Phase 3: 統合・リスク管理構築 | ④⑤層の構築 | バックテストで最大ドローダウン **15%以内**、期待値ベースでの月次プラス率 **50%以上** |
| Phase 4: フォワードテスト | 紙トレードでの実データ検証 | 最低 **8週間** の紙トレードで、バックテスト予測との乖離 **±20%以内**（過学習チェック）、シャープレシオ **1.0以上** を維持 |
| Phase 5: 実資金段階導入 | 総資産の **5%以下** からスタート | 3ヶ月間の実績がフォワードテスト目標を下回らなければ段階的に資金を拡大。実資金ベースの最大許容ドローダウン **15%** に達したら自動停止し、本方針を見直す |

### 5.3 評価層の継続KPI（4.1の目標値）
- ②パターン認識層: 方向的中率 **55%以上**（単体シャープレシオ0.8以上は参考値。主要採否基準は5.4参照）
- ③LLM特徴量層: イベント検知的中率 **60%以上**、③あり/なしでシャープレシオ **+0.2以上** の増分効果
- ④統合判断層: 統合後の成績が②単体を **常に上回ること**（下回れば統合ロジックを見直す）
- ⑤リスク管理層: 最大ドローダウン **15%以内**、実現ボラティリティが目標レンジ内

上記の数値は初期仮説値であり、Phase 1のPoC結果を踏まえて妥当性を検証・調整する（変更時は本ドキュメントの変更履歴に記録すること）。

### 5.4 個別スリーブ（施策）の採否基準（2026-07-05改訂）
外部アドバイザーレビュー（[20260704-外部アドバイザー評価-行き詰まり打破の視点転換](../85レビュー/20260704-外部アドバイザー評価-行き詰まり打破の視点転換.md)）を踏まえ、個別スリーブ・施策の採否基準を以下の通り改訂する。

- **旧基準**（〜2026-07-04まで運用）: 「スリーブ単体のシャープレシオが0.8以上か」を主要な採否基準としていた。この基準は、単体では弱くても他スリーブと低相関で分散価値のある施策（例: OBS000029のクロスセクション系）を「単体で弱い」という理由だけで一律不採用にしてしまうバイアスがあった。
- **新基準**: スリーブ・施策の採否は **ポートフォリオへの限界寄与** を主軸に判定する。
  1. 既存の主軸（②モメンタムL=30・scale=30）との相関が低いこと（目安 \|ρ\|<0.3程度）
  2. 合成した際に、確認（未見）期間で **ポートフォリオSharpeが改善** する、または **最大ドローダウンが削減** されること
  3. 上記が確認できれば、スリーブ単体のシャープレシオが0.8未満（場合によっては0.4程度）でも採用候補とする。単体シャープレシオは参考値として引き続き記録するが、それ単独では不採用の理由にしない。
  4. 予測単位での有意性検証（G1相当のkill基準）は従来通り必須。単体で無エッジなもの（例: OBS000027, OBS000029のG1）は本基準の対象以前に打ち切る。
- **North Star（5.1）Sharpe1.5との関係**: `IR ≈ IC × √ブレッド` の関係上、現行の「1資産×日足×単一方向」という構成（年間ベット数が少ない＝ブレッドが小さい）のままでは、1.5到達に必要なICの水準が非現実的になりやすい。1.5を維持する場合は、ブレッド（銘柄数・頻度等の独立ベット数）を増やす投資とセットで計画することを前提とする。5.1の数値自体は本改訂では変更しないが、今後のロードマップ検討（ユニバース拡張・高頻度化等）はこの関係を踏まえて評価する。
